@@ brief
- Spark tourne sur la **JVM** : il lui faut Java. Spark 4 demande Java **17 ou 21**. La vidéo installe Java 11 et Spark 3.0.3 à la main : c'est l'ancienne méthode.
- Aujourd'hui, le paquet Python `pyspark` contient Spark lui-même. `uv add pyspark` suffit : pas d'archive à télécharger, pas de `SPARK_HOME` à régler.
- Un programme Spark commence par une **SparkSession** : `SparkSession.builder.master("local[*]").getOrCreate()`. `local[*]` veut dire « sur cette machine, avec tous ses cœurs ».
- Tant que la session tourne, Spark ouvre une **interface web** sur le port **4040** : les jobs, leurs étapes et leurs tâches. Elle disparaît avec la session.

@@ codespaces
- L'image Python de ton devcontainer (module 0) n'a pas Java. La façon propre de l'ajouter : une **feature** dans `.devcontainer/devcontainer.json`, puis une reconstruction du Codespace. Ainsi, chaque nouveau Codespace l'aura.
- Dans un Codespace, un port ouvert apparaît dans l'onglet **Ports** de VS Code : un clic sur l'icône du globe ouvre l'interface de Spark dans ton navigateur.

@@ verified

@@ predict

@@ predict-answer
Plus tard, à la création de la `SparkSession`. `import pyspark` ne charge que du Python, qui marche sans Java. C'est `getOrCreate()` qui démarre la JVM de Spark, et c'est là que l'erreur arrive : `[JAVA_GATEWAY_EXITED] Java gateway process exited before sending its port number`. Le Python de PySpark parle à une JVM : sans elle, il n'y a pas de Spark.

### 1. La feature Java

Dans `.devcontainer/devcontainer.json`, sous `features`, ajoute la feature Java du catalogue [containers.dev/features](https://containers.dev/features) : son adresse est `ghcr.io/devcontainers/features/java:1`, et sa valeur un objet avec la version, `{ "version": "21" }`. Commite, pousse, puis **Rebuild Container** depuis la palette de commandes. Vérifie avec `java -version`.

### 2. Le projet

~~~bash
mkdir -p /workspaces/data-engineering-zoomcamp/mon-travail/module-06
cd /workspaces/data-engineering-zoomcamp/mon-travail/module-06
uv init --bare
uv add pyspark
~~~

### 3. Le test

Écris `test_spark.py` : une session `local[*]`, un `print` de `spark.version`, puis `spark.range(10).show()` et `spark.stop()`. Lance-le avec `uv run python test_spark.py`. Les lignes `WARN` du début sont normales.

### 4. L'interface web

Elle ne vit que pendant la session. Écris `ui.py` : une session, un petit calcul (`spark.range(1_000_000).selectExpr("sum(id)").show()`), puis `input("Regarde le port 4040, puis appuie sur Entrée")` avant `spark.stop()`. Lance-le, ouvre l'onglet **Ports**, puis le port 4040. Clique sur le job : combien d'étapes, combien de tâches ?

Le `.gitignore` de ton fork ignore déjà les `.parquet` et les `.csv`, mais pas les `.csv.gz` que tu vas télécharger. Ajoute une ligne `mon-travail/module-06/data/`, et vérifie avec `git check-ignore -v mon-travail/module-06/data/x.csv.gz`.

@@ hints
- Après `Rebuild Container`, ouvre un **nouveau** terminal : l'ancien garde les anciennes variables.
- `uv init --bare` crée seulement le `pyproject.toml`, sans fichier d'exemple.
- Si le port 4040 n'apparaît pas, c'est que la session s'est déjà arrêtée : le `input()` la garde ouverte.
- Si 4040 est pris (une autre session Spark tourne), Spark prend le suivant, 4041, et le dit dans ses premières lignes.

@@ breakfix
La vidéo règle `JAVA_HOME` sur un Java 11 téléchargé à la main. Fais comme si tu suivais la vidéo : `export JAVA_HOME=$HOME/spark/jdk-11.0.1`, puis relance `uv run python test_spark.py`. Lis l'erreur depuis le début, pas seulement la dernière ligne. Puis répare.

@@ breakfix-hints
- La dernière ligne parle d'une « Java gateway ». La vraie cause est **au-dessus**.
- Cherche une ligne qui contient `bin/java`.
- `unset JAVA_HOME` retire la variable de ce terminal.

@@ breakfix-answer
~~~text
.../pyspark/bin/spark-class: line 71: /root/spark/jdk-11.0.1/bin/java: No such file or directory
...
pyspark.errors.exceptions.base.PySparkRuntimeError: [JAVA_GATEWAY_EXITED] Java gateway process exited before sending its port number.
~~~

(Le début du chemin dépend de ton dossier personnel.) Quand `JAVA_HOME` est réglé, Spark l'utilise sans vérifier : il cherche `bin/java` dans ce dossier, qui n'existe pas. La dernière ligne ne dit que la conséquence ; la cause est la première ligne. `unset JAVA_HOME` répare ce terminal. Et même avec ce dossier, Java 11 ne marcherait pas : Spark 4 demande 17 ou plus. Règle générale : dans une longue erreur, la cause est souvent la première ligne, pas la dernière.
