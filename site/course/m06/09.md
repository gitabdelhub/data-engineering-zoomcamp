@@ brief
- 🔑 Sous chaque DataFrame, il y a un **RDD** (*Resilient Distributed Dataset*) : une collection d'objets Python répartie en partitions. `df.rdd` y donne accès, chaque ligne y est un `Row`.
- Les opérations des RDD sont plus bas niveau : `filter`, `map` (une ligne donne une ligne), `reduceByKey` (combine les valeurs d'une même clé), puis `toDF()` pour revenir à un DataFrame.
- 🔑 `reduceByKey` attend des **paires** `(clé, valeur)` : c'est ainsi que Spark sait quoi mélanger dans le shuffle.
- `mapPartitions` reçoit **une partition entière** à la fois (un itérateur de lignes) : utile pour un traitement coûteux à préparer, comme charger un modèle de machine learning une fois par partition.

@@ codespaces

@@ guide
### 1. Les paires

Un exemple sur des ventes, à adapter :

~~~python
def to_pair(row):
    key = (row.day, row.shop)
    value = (row.amount, 1)
    return (key, value)

def combine(left, right):
    return (left[0] + right[0], left[1] + right[1])

totals = sales.rdd.map(to_pair).reduceByKey(combine)
~~~

### 2. L'heure

`row.lpep_pickup_datetime` est un `datetime` Python : `.replace(minute=0, second=0, microsecond=0)` garde l'heure.

### 3. Revenir au DataFrame

Après `reduceByKey`, chaque élément est `((heure, zone), (montant, nombre))`. Un `map` l'aplatit en un tuple de quatre valeurs, puis `toDF(["hour", "zone", "amount", "number_records"])`.

### 4. mapPartitions

Une fonction qui reçoit un itérateur et renvoie une liste (ou fait `yield`). Pour compter sans tout garder en mémoire : `sum(1 for _ in rows)`.

@@ hints
- Le filtre compare un `datetime` avec un `datetime` : `datetime(2020, 1, 1)`, pas une chaîne.
- Si l'erreur arrive à l'action et pas au `map`, c'est normal : les RDD sont paresseux aussi.
- `getNumPartitions()` existe aussi sur un RDD : il doit valoir le nombre d'éléments de ton résultat de `mapPartitions`.

@@ solution
`rdd.py` :

~~~python
from datetime import datetime
from pyspark.sql import SparkSession

spark = SparkSession.builder.master("local[*]").appName("rdd").getOrCreate()
rdd = spark.read.parquet("data/pq/green/*/*") \
    .select("lpep_pickup_datetime", "PULocationID", "total_amount").rdd

start = datetime(2020, 1, 1)


def to_pair(row):
    hour = row.lpep_pickup_datetime.replace(minute=0, second=0, microsecond=0)
    return ((hour, row.PULocationID), (row.total_amount, 1))


def combine(left, right):
    return (left[0] + right[0], left[1] + right[1])


def unwrap(item):
    (hour, zone), (amount, count) = item
    return (hour, zone, amount, count)


result = rdd.filter(lambda row: row.lpep_pickup_datetime >= start) \
    .map(to_pair) \
    .reduceByKey(combine) \
    .map(unwrap) \
    .toDF(["hour", "zone", "amount", "number_records"])
print(result.count(), "lignes")


def count_rows(rows):
    yield sum(1 for _ in rows)


print(rdd.mapPartitions(count_rows).collect())
spark.stop()
~~~

La sortie : `744767 lignes`, puis `[1141148, 438057, 432402, 292910]` sur 4 cœurs.

@@ breakfix
Un collègue écrit son `map` ainsi : `lambda row: (heure, row.PULocationID, row.total_amount)`, sans paire, puis `reduceByKey(lambda a, b: a + b)`. Lance-le. **À quelle ligne** l'erreur apparaît-elle, et que dit-elle ? Répare.

@@ breakfix-hints
- L'erreur vient d'un worker Python : cherche une ligne qui contient `Error:` dans la trace.
- Compte les éléments de son tuple, et ce que `reduceByKey` attend.
- Rien ne casse avant l'action : `take` ou `count`.

@@ breakfix-answer
L'erreur apparaît à l'**action** (`take`, `count`…), pas au `map` : `ValueError: too many values to unpack (expected 2)`. `reduceByKey` découpe chaque élément en `(clé, valeur)`, et reçoit trois valeurs. La réparation : une clé composée, `((heure, zone), montant)`. Deux leçons d'un coup : une erreur dans du code paresseux se montre là où le calcul part, souvent loin de la ligne fautive ; et une trace de Spark contient l'erreur Python au milieu d'une pile Java.
