@@ brief
- Pour la suite du module, il te faut deux ans de taxis **verts** et **jaunes** (2020 et 2021), en CSV compressés publiés par DataTalksClub, un fichier par mois.
- Le cours les range en `data/raw/{type}/{année}/{mois}/`, puis les convertit en parquet dans `data/pq/{type}/{année}/{mois}/`. Ce rangement par dossiers permet de lire un mois, une année ou tout avec un seul **motif** : `data/pq/green/*/*`.
- La conversion se fait avec un **schéma** par type de taxi : les colonnes des verts (`lpep_…`) et des jaunes (`tpep_…`) ne sont pas les mêmes.
- Une boucle Python sur les mois et les types lance autant de lectures et d'écritures : Spark se pilote avec du Python ordinaire.

@@ codespaces
- Le téléchargement fait environ 730 Mo (40 Mo de verts, 690 Mo de jaunes), et le parquet environ 1,2 Go. Vérifie la place avec `df -h /workspaces` avant de commencer : un Codespace de base a 32 Go.
- La conversion prend environ 5 minutes sur 4 cœurs, presque tout pour les jaunes.

@@ verified
- Testé avec PySpark 4.2.1 : après conversion, 2 304 517 trajets verts et 39 649 199 jaunes, les mêmes nombres que dans la vidéo.
- **Le piège du script officiel** : DataTalksClub ne publie 2021 que de janvier à **juillet**. `download_data.sh` boucle sur 12 mois, avec `set -e` : au mois d'août, `wget` échoue, laisse un fichier **vide**, et le script s'arrête. Tu le vois dans le breakfix.

@@ predict-answer
Autre chose : **4** sur 4 cœurs. Les 76 fichiers des verts sont petits (66 Mo en tout) : Spark les regroupe pour remplir des partitions de taille raisonnable. Pour les jaunes (1,1 Go), il en crée 12. @@ hints
- `wget` renvoie un code différent de 0 quand l'adresse répond 404 : `if ! wget ...; then rm -f fichier; fi`.
- Avec `set -e`, une commande dans un `if` ne fait pas s'arrêter le script.
- `spark.read.csv` accepte un **dossier** : il lit tous les fichiers dedans.
- `{month:02d}` écrit `01`, `02`… comme les dossiers du script de téléchargement.
- Si ton comptage est trop petit, regarde quel mois manque avec `ls data/pq/yellow/2020`.

@@ solution
`telecharger.sh` :

~~~bash
#!/bin/bash
set -e

TAXI_TYPE=$1   # green ou yellow
YEAR=$2        # 2020 ou 2021
URL_PREFIX="https://github.com/DataTalksClub/nyc-tlc-data/releases/download"

for MONTH in {1..12}; do
  FMONTH=$(printf "%02d" "${MONTH}")
  URL="${URL_PREFIX}/${TAXI_TYPE}/${TAXI_TYPE}_tripdata_${YEAR}-${FMONTH}.csv.gz"
  LOCAL_PREFIX="data/raw/${TAXI_TYPE}/${YEAR}/${FMONTH}"
  LOCAL_PATH="${LOCAL_PREFIX}/${TAXI_TYPE}_tripdata_${YEAR}_${FMONTH}.csv.gz"

  mkdir -p "${LOCAL_PREFIX}"
  if ! wget -q "${URL}" -O "${LOCAL_PATH}"; then
    echo "${YEAR}-${FMONTH} absent, je passe"
    rm -f "${LOCAL_PATH}"
    rmdir "${LOCAL_PREFIX}"
  fi
done
~~~

`preparer.py` :

~~~python
import os
from pyspark.sql import SparkSession
from schemas import green_schema, yellow_schema

spark = SparkSession.builder.master("local[*]").appName("preparer").getOrCreate()

for taxi, schema in [("green", green_schema), ("yellow", yellow_schema)]:
    for year in (2020, 2021):
        for month in range(1, 13):
            source = f"data/raw/{taxi}/{year}/{month:02d}/"
            if not os.path.isdir(source):
                continue  # 2021 s'arrête en juillet
            print(f"{taxi} {year}-{month:02d}")
            df = spark.read.option("header", "true").schema(schema).csv(source)
            df.repartition(4).write.parquet(f"data/pq/{taxi}/{year}/{month:02d}/", mode="overwrite")

spark.stop()
~~~

`schemas.py` : les deux `StructType` du notebook `05_taxi_schema.ipynb`, sous les noms `green_schema` et `yellow_schema`. Le comptage final affiche 2 304 517 et 39 649 199.

@@ breakfix
Lance le script **officiel**, sans le modifier : `bash ../../06-batch/code/download_data.sh yellow 2021` depuis `mon-travail/module-06`. Il s'arrête : à quel mois, et pourquoi ? Puis lance `ls -la data/raw/yellow/2021/08/`. Qu'est-ce qui traîne, et quel problème ça poserait à la conversion ?

@@ breakfix-hints
- La dernière ligne de `wget` donne un code HTTP.
- `ls -la` affiche la taille de chaque fichier.
- Un dossier `08` qui existe, même avec un fichier vide, passe le test `os.path.isdir` de ton `preparer.py`.

@@ breakfix-answer
Il s'arrête en **août** : `wget` reçoit `404 Not Found`, parce que DataTalksClub n'a publié que janvier à juillet 2021, et `set -e` arrête le script à la première erreur. Mais `wget -O` a déjà créé le fichier de destination avant de télécharger : il reste un `yellow_tripdata_2021_08.csv.gz` de **0 octet**. Ton `preparer.py` trouverait le dossier `08`, et tenterait de lire un fichier vide. Les fichiers vides sont des pièges discrets : supprime-les (`find data/raw -size 0 -delete`, puis `rmdir` des dossiers vides), et c'est pour ça que ton script les nettoie lui-même.
