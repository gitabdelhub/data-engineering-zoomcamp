@@ brief
- Un **DataFrame** Spark ressemble à un tableau pandas, mais il est réparti en partitions. `select`, `filter`, `withColumn` et `groupBy` s'enchaînent comme en pandas.
- 🔑 Ces opérations sont des **transformations** : elles sont **paresseuses** (*lazy*). Spark note ce qu'il faut faire, sans rien calculer.
- 🔑 Le calcul ne part qu'avec une **action** : `show()`, `count()`, `collect()`, `take()`, ou une écriture. Spark optimise alors toute la chaîne d'un coup.
- Le module `pyspark.sql.functions` (importé en `F`) contient des centaines de fonctions : `F.to_date`, `F.col`, `F.lit`… Pour une logique qu'il n'a pas, une **UDF** (*user-defined function*) applique ta fonction Python à chaque ligne, en plus lent.

### 1. Transformations et actions

Un exemple sur des ventes, à adapter :

~~~python
import time
from pyspark.sql import functions as F

t0 = time.time()
grosses = ventes.filter(ventes.amount > 100).select("shop", "amount")
print("transformation :", round(time.time() - t0, 2), "s")

t0 = time.time()
print(grosses.count(), "ventes,", round(time.time() - t0, 2), "s")
~~~

### 2. Les dates

`F.to_date(colonne)` garde la date d'un timestamp. Un `withColumn("pickup_date", ...)` ajoute la colonne, puis tu filtres dessus.

### 3. Le classement

`groupBy(...).count()` crée une colonne `count`. `orderBy(F.desc("count"))` la trie, puis `show(5)`.

### 4. L'UDF

~~~python
from pyspark.sql import types

def initiale(nom):
    return nom[0].upper()

initiale_udf = F.udf(initiale, returnType=types.StringType())
ventes.withColumn("shop_initial", initiale_udf(ventes.shop)).show(5)
~~~

@@ solution
`explore.py` :

~~~python
import time
from pyspark.sql import SparkSession, functions as F, types

spark = SparkSession.builder.master("local[*]").appName("explore").getOrCreate()
df = spark.read.parquet("data/pq/fhvhv/2021/01/")

t0 = time.time()
hv3 = df.filter(df.hvfhs_license_num == "HV0003")
print("transformation :", round(time.time() - t0, 2), "s")
t0 = time.time()
print("HV0003 :", hv3.count(), "trajets,", round(time.time() - t0, 2), "s")

with_date = df.withColumn("pickup_date", F.to_date(df.pickup_datetime))
print("15 janvier :", with_date.filter(with_date.pickup_date == "2021-01-15").count())

df.groupBy("dispatching_base_num").count().orderBy(F.desc("count")).show(5)


def crazy_stuff(base_num):
    num = int(base_num[1:])
    if num % 7 == 0:
        return f"s/{num:03x}"
    elif num % 3 == 0:
        return f"a/{num:03x}"
    else:
        return f"e/{num:03x}"


crazy_stuff_udf = F.udf(crazy_stuff, returnType=types.StringType())
df.withColumn("base_id", crazy_stuff_udf(df.dispatching_base_num)) \
  .select("dispatching_base_num", "base_id").show(5)
spark.stop()
~~~

Les nombres : 8 704 128 trajets HV0003, 443 059 le 15 janvier, et la première base du classement est `B02510`, avec 3 091 000 trajets. La base `B02682` donne `a/a7a`.

@@ breakfix-answer
Il trouve **1** trajet, au lieu de 443 059. La colonne est un timestamp : Spark transforme `"2021-01-15"` en `2021-01-15 00:00:00`, et ne garde que le trajet pris en charge à minuit pile. Aucune erreur, juste un mauvais nombre. Correction 1 : `F.to_date(df.pickup_datetime) == "2021-01-15"`. Correction 2 : un intervalle, `(df.pickup_datetime >= "2021-01-15") & (df.pickup_datetime < "2021-01-16")`. La seconde est souvent plus rapide sur de gros volumes : Spark peut sauter des blocs du parquet grâce aux minimums et maximums qu'il y range. C'est le piège de l'intervalle du module 5, en plus discret.
