# Une vraie API, page par page

Une **API web** est une adresse qui renvoie des données, en général en **JSON**, au lieu d'une page à lire. Celle d'Open Library, la bibliothèque en ligne d'Internet Archive, cherche des livres :

```text
https://openlibrary.org/search.json?q=harry+potter&limit=100&offset=0
```

Ouvre-la dans un onglet de ton navigateur. La réponse ressemble à ceci, en très raccourci :

```json
{
  "numFound": 1234,
  "start": 0,
  "docs": [
    {"key": "/works/OL82563W", "title": "Harry Potter and the Philosopher's Stone", "author_name": ["J. K. Rowling"], "first_publish_year": 1997},
    ...
  ]
}
```

Trois choses à repérer avant d'écrire une ligne de code : **où est la liste** des livres (`docs`), **combien il y en a en tout** (`numFound`), et **comment demander la suite** (les paramètres `limit` et `offset`).

## La pagination

Une API ne renvoie jamais des milliers de résultats d'un coup : elle les découpe en **pages**. Il existe quelques façons classiques de demander la page suivante :

| Style | La requête suivante | Le type dans dlt |
| --- | --- | --- |
| Décalage | `?offset=100&limit=100` : « saute les 100 premiers » | `offset` |
| Numéro de page | `?page=2` | `page_number` |
| Lien dans la réponse | la réponse contient `"next": "https://..."` | `json_link` |
| Curseur | la réponse contient un jeton à renvoyer | `cursor` |

Pour savoir quand **s'arrêter**, le paginateur a besoin d'un signal : le total (`total_path`), un nombre maximum, ou simplement une **page vide**.

## La source REST API de dlt

Pour une API REST, pas besoin d'écrire la boucle des pages toi-même : `rest_api_source` la fait, à partir d'une configuration. Un exemple sur une API imaginaire de films, paginée par numéro de page :

```python
from dlt.sources.rest_api import rest_api_source

source = rest_api_source({
    "client": {"base_url": "https://api.exemple.com/v1/"},
    "resource_defaults": {"primary_key": "id", "write_disposition": "replace"},
    "resources": [
        {
            "name": "films",
            "endpoint": {
                "path": "films",
                "params": {"genre": "comedie"},
                "data_selector": "results",
                "paginator": {"type": "page_number", "page_param": "page", "base_page": 1, "total_path": "total_pages"},
            },
        },
    ],
})
```

- `client.base_url` : le début commun de toutes les adresses de l'API.
- `resources` : une entrée par **table**. `endpoint.path` est ajouté à `base_url`, `params` devient la fin de l'adresse (`?genre=comedie`).
- `data_selector` : où se trouve la liste dans la réponse. Ici, `{"results": [...]}`.
- `resource_defaults` : les réglages communs à toutes les ressources. `primary_key` dit quelle colonne identifie un enregistrement.

La source se lance comme une ressource : `pipeline.run(source)`.

@@ hints
- La liste est dans `docs`, le total dans `numFound` (avec un **N** majuscule).
- `"paginator": {"type": "offset", "limit": 100, "offset_param": "offset", "limit_param": "limit", "total_path": "numFound", "maximum_offset": 500}`
- Mets aussi `"limit": 100` dans `params` : c'est le paginateur qui l'envoie, mais l'écrire des deux côtés rend la configuration plus lisible.
- Si dlt affiche `Total ... not found in the response`, le nom dans `total_path` n'existe pas dans la réponse : vérifie les majuscules.

@@ solution
Le fichier officiel du cours est `cohorts/2026/workshops/dlt/open_library_pipeline.py`, dans ton fork. Voici la même idée, avec la limite de 500 livres et des commentaires :

~~~python
import dlt
from dlt.sources.rest_api import rest_api_source


def open_library_source(query: str):
    return rest_api_source({
        "client": {
            "base_url": "https://openlibrary.org",
        },
        "resource_defaults": {
            "primary_key": "key",              # "/works/OL82563W" identifie un livre
            "write_disposition": "replace",    # chaque lancement remplace la table
        },
        "resources": [
            {
                "name": "books",
                "endpoint": {
                    "path": "search.json",
                    "params": {"q": query, "limit": 100},
                    "data_selector": "docs",   # la liste des livres est dans "docs"
                    "paginator": {
                        "type": "offset",
                        "limit": 100,
                        "offset_param": "offset",
                        "limit_param": "limit",
                        "total_path": "numFound",   # s'arrête au total...
                        "maximum_offset": 500,      # ...ou à 500 livres
                    },
                },
            },
        ],
    })


if __name__ == "__main__":
    pipeline = dlt.pipeline(
        pipeline_name="open_library_pipeline",
        destination="duckdb",
        dataset_name="open_library_data",
        progress="log",
    )
    print(pipeline.run(open_library_source("tolkien")))
    print(pipeline.dataset().row_counts().df())
~~~

La sortie se termine par le nombre de lignes, par exemple :

~~~text
            table_name  row_count
0                books        500
1   books__author_name        612
2      books__language        801
...
~~~

Les tables enfants et leurs nombres dépendent de ta recherche : chaque clé qui contient une liste (`author_name`, `language`, et d'autres) devient une table `books__...`.
