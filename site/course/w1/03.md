# Explorer ce que dlt a chargé

Ton pipeline a tourné. Avant de t'en servir, tu vérifies **ce qu'il a vraiment chargé** : quelles tables, quelles colonnes, combien de lignes, et si les valeurs ont du sens. Trois outils pour ça, du plus visuel au plus précis.

## Le tableau de bord de dlt

dlt a un tableau de bord web, construit avec **marimo** (un genre de notebook). Il a besoin de trois bibliothèques en plus :

```bash
uv add marimo pyarrow "ibis-framework[duckdb]"
uv run dlt pipeline open_library_pipeline show
```

Il s'ouvre sur le port **2718**. Tu y trouves, de haut en bas :

- le **dernier lancement** : la durée de chaque étape (Extract, Normalize, Load) ;
- **Browse Data** : la liste des tables avec, sur un bouton, leur nombre de lignes, et une zone pour taper du SQL ;
- **Inspect Schema** : chaque table, ses colonnes, leurs types, et la clé primaire ;
- **Pipeline Loads** : l'historique des chargements, avec leur `load_id`.

## Le dataset, depuis Python

Ce que tu as vu à la leçon 1 marche avec n'importe quel pipeline, même depuis un autre script : `dlt.attach` retrouve un pipeline par son nom.

```python
import dlt

pipeline = dlt.attach("cinema")
ds = pipeline.dataset()
print(ds.tables)                                  # la liste des tables
print(ds.films.select("titre", "annee").limit(5).df())
print(ds("SELECT annee, COUNT(*) AS n FROM films GROUP BY annee ORDER BY n DESC").df())
```

`ds.films` est une **relation** : rien n'est lu tant que tu n'appelles pas `.df()` (un DataFrame pandas) ou `.fetchall()` (une liste de tuples). Les requêtes tournent dans DuckDB, pas dans Python.

## Les tables enfants

Un livre a plusieurs auteurs : ils sont dans `books__author_name`, une ligne par auteur, la valeur dans la colonne `value`. Pour compter les livres d'un auteur, tu comptes ses lignes dans la table enfant. Pour afficher le titre à côté, tu fais une **jointure** :

```sql
SELECT f.titre, a.value AS acteur
FROM films f
JOIN films__acteurs a ON a._dlt_parent_id = f._dlt_id
```

@@ brief
- Un pipeline vert ne suffit pas : regarde toujours **ce qui a été chargé**. Tables, colonnes, types, nombres de lignes.
- `uv run dlt pipeline <nom> show` ouvre le **tableau de bord** de dlt, sur le port 2718.
- `dlt.attach("<nom>").dataset()` retrouve les tables depuis n'importe quel script. `.df()` pour pandas, `ds("SELECT ...")` pour du SQL.
- Les listes sont dans des tables enfants : on les relie avec `_dlt_parent_id = _dlt_id`.

@@ codespaces
- Quand le tableau de bord démarre, VS Code propose d'**ouvrir le port 2718 dans le navigateur**. Sinon, onglet **Ports**, ligne 2718, icône du globe.
- Le tableau de bord tourne tant que la commande tourne. `Ctrl+C` dans le terminal l'arrête.
- Tu peux garder le tableau de bord ouvert pendant que tes scripts tournent. Après un nouveau chargement, recharge sa page pour voir les nouvelles données.

@@ verified
- Le tableau de bord, `dlt.attach` et les requêtes ont été testés avec dlt 1.31.0, marimo 0.25, sur les tables Open Library de la leçon 2 (chargées depuis ma copie locale de l'API).
- Le guide officiel installe `dlt[workspace]` pour le tableau de bord. Avec dlt 1.31, il faut à la place `marimo`, `pyarrow` et `ibis-framework` : c'est dlt lui-même qui le dit, si tu lances `show` sans eux.

@@ hints
- `ds("...")` prend une requête SQL entière, et `.df()` l'affiche joliment.
- Les tables enfants d'Open Library s'appellent `books__author_name` et `books__language`. Les noms exacts sont dans **Inspect Schema**.
- Sans filtre, le résultat dépend de la place des `NULL` dans le tri : DuckDB les met à la fin, d'autres bases au début. Avec `WHERE first_publish_year IS NOT NULL`, ta requête donne la bonne réponse partout.

@@ solution
~~~python
import dlt

# Retrouve le pipeline de la leçon 2 par son nom : pas de nouvel appel à l'API
pipeline = dlt.attach("open_library_pipeline")
ds = pipeline.dataset()

# 1. Les 10 auteurs les plus présents : on compte leurs lignes dans la table enfant
print(ds("""
    SELECT value AS auteur, COUNT(*) AS livres
    FROM books__author_name
    GROUP BY value
    ORDER BY livres DESC
    LIMIT 10
""").df())

# 2. Les livres par langue
print(ds("""
    SELECT value AS langue, COUNT(*) AS livres
    FROM books__language
    GROUP BY value
    ORDER BY livres DESC
""").df())

# 3. Le livre le plus ancien, parmi ceux qui ont une année
print(ds("""
    SELECT title, first_publish_year
    FROM books
    WHERE first_publish_year IS NOT NULL
    ORDER BY first_publish_year
    LIMIT 1
""").df())
~~~

Les réponses dépendent de ta recherche. Additionne les livres de toutes les langues : tu dépasses le nombre de lignes de `books`, car un livre traduit compte une fois **par langue**.

@@ breakfix
Fais comme si une mise à jour arrivait : `uv add "sqlglot>=30.22"`, puis relance `uv run python explorer.py`. Lis l'erreur jusqu'au bout. Explique d'où elle vient, puis répare ton projet pour qu'il remarche.

@@ breakfix-hints
- La dernière ligne de l'erreur parle d'une fonction `qualify()` et d'un argument qu'elle ne connaît pas. Ce n'est pas ton code : regarde les noms de fichiers dans la trace, `dlt/dataset/lineage.py`.
- dlt 1.31 a été écrit pour les versions de sqlglot d'avant le 9 octobre 2026. Que dit `uv tree | grep sqlglot` ?
- `uv add "sqlglot<30.22"` remet la contrainte, et `uv.lock` retient la bonne version.

@@ breakfix-answer
~~~text
TypeError: qualify() got an unexpected keyword argument 'infer_schema'
~~~

Ce n'est ni ton code ni tes données : dlt appelle une fonction de **sqlglot** (la bibliothèque qui analyse le SQL), et la version 30.22 de sqlglot a changé cette fonction. dlt 1.31.0 accepte n'importe quel sqlglot à partir de la 26.32, sans limite haute : une version trop récente casse donc dlt dès qu'il lit des données. Remets `uv add "sqlglot<30.22"` : `pyproject.toml` garde la contrainte, et `uv.lock` la version exacte qui marche. C'est pour ça qu'on commite `uv.lock` : la même installation, sur chaque machine, chaque jour.

Une version plus récente de dlt corrigera sans doute ce problème. Quand tu changeras de version de dlt, essaie de retirer la contrainte, et garde-la si l'erreur revient.
