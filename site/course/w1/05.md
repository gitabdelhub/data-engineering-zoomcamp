@@ brief
- Le cours officiel montre une autre façon de travailler : un **agent IA** dans l'éditeur écrit le pipeline à partir d'une description, et le **serveur MCP de dlt** lui donne la documentation de dlt et les métadonnées de ton pipeline.
- Cette leçon est **facultative**. Elle vient après les autres exprès : tu sais maintenant écrire ce pipeline toi-même, donc tu peux juger le code de l'IA, au lieu de le croire.
- 🔑 La règle d'un bon data engineer avec une IA : elle propose, **tu vérifies**. Les nombres de lignes, les tables enfants, le paginateur, la clé primaire.

@@ codespaces
- Dans ton Codespace, l'agent IA le plus simple est **GitHub Copilot**, dans VS Code : l'icône de discussion en haut, puis le mode **Agent**. GitHub propose un forfait Copilot gratuit, limité chaque mois.
- Un serveur MCP pour VS Code se déclare dans `.vscode/mcp.json`, à la racine du dossier ouvert. Le texte exact est dans le guide officiel ci-dessus, section « VS Code (Copilot) ».
- Le guide officiel dit `pip install "dlt[workspace]"`. Avec dlt 1.31, cet extra n'existe plus : la commande `dlt ai` dit elle-même qu'elle est maintenant dans `dlt[hub]`.

@@ guide
### 1. Le dossier

~~~bash
mkdir -p /workspaces/data-engineering-zoomcamp/mon-travail/workshop-dlt/ia
cd /workspaces/data-engineering-zoomcamp/mon-travail/workshop-dlt/ia
~~~

### 2. Le serveur MCP (facultatif)

Suis la section « Step 2 » du guide officiel ci-dessus, pour VS Code. Le serveur MCP tourne avec `uv run`, donc il n'y a rien d'autre à installer.

### 3. La demande à l'agent

Inspire-toi de l'exemple de demande du guide officiel (Step 5), mais donne **tes** contraintes : la recherche, le nom du pipeline, la limite de 500 livres, `merge` sur `key`. Plus ta demande est précise, plus le code est juste.

### 4. Vérifie comme d'habitude

Lance son script, puis compte les lignes, ouvre le tableau de bord, relance une deuxième fois. Note ce que tu observes.

### 5. Compare

Ouvre les deux fichiers côte à côte : clic droit sur un fichier, **Select for Compare**, puis clic droit sur l'autre, **Compare with Selected**.

@@ hints
- Si l'agent invente une option de configuration, la documentation de la source REST API tranche : chaque clé valide y est listée.
- Si son code fait la boucle des pages à la main avec `requests`, demande-lui pourquoi il n'utilise pas le paginateur de dlt.
- `dlt init dlthub:open_library duckdb` génère aussi un fichier de description de l'API pour l'IA. Il demande peut-être `dlt[hub]` : le message te le dira.

@@ solution
Pas de solution unique : le code de l'IA change d'une fois sur l'autre. Ce que contient un bon `COMPARAISON.md`, par exemple :

~~~markdown
# L'IA contre moi

1. Pagination : l'IA a utilisé `offset` avec `total_path: numFound`, comme moi,
   mais sans `maximum_offset`. Sur une recherche de 9 000 livres, elle charge tout.
   Je préfère ma version : je décide combien de pages je demande à l'API.
2. Clé primaire : l'IA a mis `primary_key: key` avec `replace`. La clé ne sert à rien
   en `replace` ; en `merge`, elle évite les doublons. Je garde `merge`.
3. Code : l'IA a ajouté une fonction de log et des commentaires partout. Plus long,
   pas plus clair. Je préfère mon fichier plus court.

Erreur repérée : la première version avait `data_selector: "results"`. Le pipeline
était vert, mais `row_counts()` plantait : aucune table books. Repéré en comptant les lignes.
~~~
