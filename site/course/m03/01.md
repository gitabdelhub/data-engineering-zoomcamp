@@ brief
- 🔑 **OLTP** (les bases des applications : petites écritures rapides, transactions) contre **OLAP** (l'analyse : énormes lectures, données rafraîchies par lots). Un **data warehouse** est une solution OLAP.
- 🔑 **BigQuery** est un data warehouse **serverless** : pas de serveur à gérer. Le stockage et le calcul sont séparés, et tu paies surtout le **volume lu** par tes requêtes.
- Tout est rangé en **projet → dataset → table**. Ton dataset `dez_dataset` vient de ton Terraform du module 1.
- 🔑 Une **table externe** ne contient rien : elle lit les fichiers de ton bucket à chaque requête. Une table **normale** (on dit aussi « matérialisée ») copie les données dans le stockage de BigQuery.
- Avant de lancer une requête, l'éditeur affiche en haut à droite **combien de données elle va lire**. C'est ton compteur de dépenses.

@@ predict-answer
**Oui**, il les lit directement : l'option `compression = 'GZIP'` de la table externe le lui dit. Mais un fichier gzip se lit forcément **du début à la fin, par un seul travailleur** : BigQuery ne peut pas le découper pour le répartir entre plusieurs machines. Avec 24 petits fichiers, ça ne se voit pas. Avec un seul gros fichier de plusieurs Go, ce serait lent, et BigQuery refuse les fichiers compressés de plus de 4 Go. C'est une des raisons pour lesquelles les data engineers préfèrent le format **Parquet**, que tu utiliseras dans le homework.

blob = bucket.blob("vacances/photo.jpg")   # le nom du fichier dans le bucket
if not blob.exists():
    blob.upload_from_filename("photo.jpg")  # le fichier sur ton disque
~~~

Un **blob**, c'est un fichier dans le bucket. Les « dossiers » n'existent pas vraiment : `vacances/` fait simplement partie du nom.

### 5. La table externe

Dans la console BigQuery, clique sur **+** (nouvelle requête). Le modèle, pour une table de ventes imaginaire :

~~~sql
CREATE OR REPLACE EXTERNAL TABLE dez_dataset.ventes_ext (
  id_vente INT64,
  moment TIMESTAMP,
  produit STRING,
  montant FLOAT64
)
OPTIONS (
  format = 'CSV',
  uris = ['gs://mon-bucket/ventes/ventes_*.csv.gz'],
  compression = 'GZIP',
  skip_leading_rows = 1
);
~~~

- Les colonnes et leurs types sont écrits **dans l'ordre du CSV**. Lis la première ligne d'un de tes fichiers pour les noms : `curl -sL <adresse> | zcat | head -2`.
- `INT64` pour les nombres entiers (identifiants, codes), `FLOAT64` pour les montants et les distances, `TIMESTAMP` pour les dates et heures, `STRING` pour le texte.
- L'étoile `*` dans `uris` remplace n'importe quel texte : un seul motif peut couvrir les 24 fichiers.
- `skip_leading_rows = 1` saute la ligne des titres de chaque fichier.
- Sans projet devant le dataset, BigQuery utilise le projet choisi en haut de la console.

`mon-travail/module-03/charger_gcs.py` :

~~~python
import os
import sys
import urllib.request

from google.cloud import storage

TAXI = "green"
YEARS = ["2019", "2020"]
BASE_URL = "https://github.com/DataTalksClub/nyc-tlc-data/releases/download"

# Le nom du bucket vient de l'environnement : rien de propre à ton compte dans le code
bucket_name = os.environ.get("GCP_BUCKET")
if not bucket_name:
    sys.exit("Définis d'abord GCP_BUCKET, par exemple : export GCP_BUCKET=mon-projet-dez-lake")

# La clé est trouvée grâce à GOOGLE_APPLICATION_CREDENTIALS (leçon 1-13)
bucket = storage.Client().bucket(bucket_name)

for year in YEARS:
    for month in range(1, 13):
        name = f"{TAXI}_tripdata_{year}-{month:02d}.csv.gz"
        blob = bucket.blob(f"{TAXI}/{name}")
        # Déjà dans le bucket : on passe, le script peut être relancé sans tout renvoyer
        if blob.exists():
            print(f"déjà là : {name}")
            continue
        urllib.request.urlretrieve(f"{BASE_URL}/{TAXI}/{name}", name)
        # On envoie le fichier compressé tel quel : BigQuery sait lire le gzip
        blob.upload_from_filename(name)
        os.remove(name)
        print(f"envoyé : {name}")
~~~
