@@ brief
- Un modèle BigQuery ML peut **sortir** de BigQuery : il s'exporte dans un bucket, au format TensorFlow (*SavedModel*).
- **TensorFlow Serving**, dans un conteneur Docker, le sert comme une API web : on lui envoie un trajet en JSON, il répond le pourboire prédit.
- Le dossier servi suit une forme imposée : `<nom du modèle>/<numéro de version>/`, avec les fichiers du modèle dedans.
- Cette leçon est **facultative**. Elle montre le chemin complet d'un modèle, de l'entrepôt jusqu'à une application, mais rien dans la suite du cours n'en dépend.

@@ codespaces
- La vidéo utilise `bq` et `gsutil`, qui ne sont pas dans ton Codespace. Ici, l'export se fait en SQL dans la console, et le téléchargement avec un petit script Python : rien à installer.
- TensorFlow Serving tourne dans Docker, dans ton Codespace. L'image pèse environ 500 Mo : supprime-la à la fin avec `docker rmi tensorflow/serving`.
- Le port 8501 n'a pas besoin d'être ouvert dans le navigateur : tu l'appelles avec `curl`, depuis le terminal du Codespace.

@@ predict-answer

@@ guide
### 1. L'export, en SQL

BigQuery sait exporter un modèle avec une requête :

~~~sql
EXPORT MODEL dez_dataset.mon_modele
OPTIONS (URI = 'gs://mon-bucket/models/mon_modele');
~~~

Lance la tienne dans la console, puis ouvre ton bucket : un dossier `models/tip_model/` contient `saved_model.pb`, un dossier `variables/`, et d'autres fichiers.

### 2. Le script de téléchargement

Comme `charger_gcs.py`, mais dans l'autre sens. Deux nouveautés :

- `bucket.list_blobs(prefix="models/tip_model/")` liste tous les fichiers dont le nom commence par ce texte ;
- `blob.download_to_filename(chemin)` télécharge un fichier. Le dossier de destination doit exister : `Path(chemin).parent.mkdir(parents=True, exist_ok=True)`.

Pour chaque fichier, garde la fin de son nom (après `models/tip_model/`) et colle-la derrière `serving_dir/tip_model/1/` : `blob.name.removeprefix(...)` enlève le début d'un texte. Saute les noms qui finissent par `/` : ce sont des dossiers vides.

### 3. Lance le script

~~~bash
cd /workspaces/data-engineering-zoomcamp/mon-travail/module-03
echo "serving_dir/" >> .gitignore
uv run --with google-cloud-storage python telecharger_modele.py
find serving_dir -type f
~~~

### 4. TensorFlow Serving

La commande de la leçon, avec `$(pwd)` à la place des accents graves, et `-d` pour lancer en arrière-plan :

~~~bash
docker run -d --name tip_serving -p 8501:8501 \
  --mount type=bind,source=$(pwd)/serving_dir/tip_model,target=/models/tip_model \
  -e MODEL_NAME=tip_model tensorflow/serving
docker logs tip_serving --tail 5
~~~

Attends la ligne qui parle de `Exporting HTTP/REST API`. Puis l'état du modèle : `curl http://localhost:8501/v1/models/tip_model`.

### 5. La prédiction

La requête de la leçon envoie un JSON avec une liste `instances`. Écris la tienne avec les **six** variables de ton modèle (pas de `payment_type` : ton modèle ne le connaît pas), les zones entre guillemets.

@@ hints
- `Not found` à l'export : le dataset et le bucket doivent être au même emplacement, comme à la leçon 1.
- `docker logs tip_serving` montre `No versions of servable tip_model found` ? Le dossier `1/` est mal placé : `saved_model.pb` doit être directement dans `serving_dir/tip_model/1/`.
- Le JSON : `{"instances": [{"passenger_count": 1, "trip_distance": 2.5, "PULocationID": "74", "DOLocationID": "75", "fare_amount": 10.5, "tolls_amount": 0.0}]}`.

@@ solution
`mon-travail/module-03/sql/06_export.sql` :

~~~sql
-- Le modèle sort de BigQuery, au format TensorFlow, dans le bucket
EXPORT MODEL dez_dataset.tip_model
OPTIONS (URI = 'gs://<ton-bucket>/models/tip_model');
~~~

`mon-travail/module-03/telecharger_modele.py` :

~~~python
import os
import sys
from pathlib import Path

from google.cloud import storage

PREFIX = "models/tip_model/"
# TensorFlow Serving attend : un dossier au nom du modèle, puis un sous-dossier par version
DEST = Path("serving_dir/tip_model/1")

bucket_name = os.environ.get("GCP_BUCKET")
if not bucket_name:
    sys.exit("Définis d'abord GCP_BUCKET, par exemple : export GCP_BUCKET=mon-projet-dez-lake")

bucket = storage.Client().bucket(bucket_name)
n = 0
for blob in bucket.list_blobs(prefix=PREFIX):
    if blob.name.endswith("/"):
        continue  # un « dossier » vide, rien à télécharger
    # models/tip_model/variables/variables.index -> serving_dir/tip_model/1/variables/variables.index
    local = DEST / blob.name.removeprefix(PREFIX)
    local.parent.mkdir(parents=True, exist_ok=True)
    blob.download_to_filename(local)
    n += 1
print(f"{n} fichiers dans {DEST}")
~~~

La prédiction :

~~~bash
curl -s -X POST http://localhost:8501/v1/models/tip_model:predict \
  -d '{"instances": [{"passenger_count": 1, "trip_distance": 2.5, "PULocationID": "74", "DOLocationID": "75", "fare_amount": 10.5, "tolls_amount": 0.0}]}'
~~~

La réponse a la forme `{"predictions": [{"predicted_tip_amount": ...}]}`. Pour une course de 10,50 $ par carte, attends-toi à un pourboire prédit entre 1,50 $ et 2 $ (une régression équivalente, calculée sur les mêmes données, donne 1,66 $).

À la fin : `docker rm -f tip_serving` puis `docker rmi tensorflow/serving`.

@@ breakfix-hints
- La réponse est un JSON avec une clé `error`, pas `predictions`.
- Le message parle d'un type (*dtype*), ou d'une conversion impossible.
- À la leçon 5, quel type as-tu donné aux zones dans `green_tips_2019` ?

@@ breakfix-answer
TensorFlow Serving répond `{"error": "..."}` avec un message sur un type qui ne correspond pas : le modèle attend une chaîne (`string`) pour `PULocationID` et `DOLocationID`, et reçoit un nombre. Ce n'est pas un caprice : à la leçon 5, tu as transformé les zones en `STRING` pour qu'elles soient des **catégories**. Le modèle exporté garde ce contrat, et toute application qui l'appelle doit le respecter. Avec les guillemets, la prédiction revient.
