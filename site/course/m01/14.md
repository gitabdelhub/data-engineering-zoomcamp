# Google Cloud sans carte bancaire

L'essai gratuit de Google Cloud demande une carte bancaire qui accepte les paiements internationaux. Si tu n'en as pas, tu peux quand même faire tout le cours. Cette leçon remplace la leçon 01-13 : elle crée le même **lac de données** (un bucket) et le même **entrepôt** (un dataset BigQuery), avec Terraform, sans rien payer et sans carte.

Si tu as fait la leçon 01-13 avec une carte, saute celle-ci.

## Ce qui marche sans carte, et ce qui ne marche pas

| Ce que le cours utilise | Sans carte | Ce que tu utilises à la place |
|---|---|---|
| **BigQuery**, l'entrepôt | ✅ oui, dans le **bac à sable** (*sandbox*) | le vrai BigQuery, avec ton compte Google |
| **Cloud Storage**, le lac (les buckets) | ❌ non | un **faux Cloud Storage** dans ton Codespace : `fake-gcs-server` |
| **Dataproc**, Spark dans le cloud (06-11) | ❌ non | ton cluster Spark local de la leçon 06-10 |
| Une machine virtuelle | ❌ non | ton Codespace, qui en est déjà une |

Les modules 4 (dbt), 7 (streaming) et le workshop dlt n'ont pas besoin de Google Cloud : ils tournent avec DuckDB ou Postgres.

## Le bac à sable BigQuery

C'est le vrai BigQuery, ouvert à tout compte Google, **sans carte et sans facturation**. Il a des règles, à connaître une fois pour toutes :

- **10 Go de stockage** et **1 To de requêtes** gratuits par mois. Un mois de taxis verts pèse environ 50 Mo : tu as de la marge, à condition de supprimer (`DROP TABLE`) les tables d'un module quand tu passes au suivant.
- **Les tables, les vues et les partitions s'effacent après 60 jours.** Si tu fais une longue pause, tu recharges tes données : tes scripts le font en une commande.
- **Pas de `INSERT`, `UPDATE`, `DELETE` ni `MERGE`** (le DML), et pas de streaming. `CREATE TABLE`, `CREATE OR REPLACE TABLE … AS SELECT`, `ALTER TABLE` et `DROP TABLE` marchent : on réécrit une table au lieu de la modifier.
- **Charger un fichier de ton Codespace** dans une table (un *load job*) est gratuit et autorisé.
- **Une table externe ne peut pas lire ton faux bucket** : il est dans ton Codespace, et BigQuery, chez Google, ne le voit pas. Tu charges donc tes fichiers directement dans des tables normales, avec le script `vers_bigquery.py` de cette leçon.

**Le piège des partitions.** Une partition par jour porte la date de ses trajets. Dans le bac à sable, une partition de plus de 60 jours expire, et les taxis de 2019 ont bien plus de 60 jours. Si tu partitionnes par date (`PARTITION BY DATE(...)`), compte les lignes juste après : si ta table est vide ou presque, partitionne plutôt par **numéro de jour**. Même idée, même économie, mais avec un entier, qui n'expire pas :

~~~sql
CREATE OR REPLACE TABLE dez_dataset.green_part
-- un numéro par jour : 17897 = le 1er janvier 2019, 18628 = le 1er janvier 2021
PARTITION BY RANGE_BUCKET(jour, GENERATE_ARRAY(17897, 18628, 1))
AS
SELECT *, UNIX_DATE(DATE(lpep_pickup_datetime)) AS jour
FROM dez_dataset.green_2019_2020;
~~~

Tes filtres portent alors sur `jour` : `WHERE jour BETWEEN UNIX_DATE('2019-03-01') AND UNIX_DATE('2019-03-31')`. Vérifie dans la console que l'estimation des octets lus baisse, comme avec une partition par date. Je n'ai pas pu vérifier ce piège moi-même, faute de bac à sable dans mon environnement : si ta table partitionnée par date garde toutes ses lignes, garde la version des leçons.

## Le faux Cloud Storage

`fake-gcs-server` est un petit serveur qui répond exactement comme l'API de Cloud Storage. Il tourne dans un conteneur Docker de ton Codespace. La bibliothèque Python `google-cloud-storage` et Terraform lui parlent **sans changer une ligne de code** : il suffit de leur dire où il est.

Pour Python, c'est une variable d'environnement : `STORAGE_EMULATOR_HOST=http://localhost:4443`. Quand elle existe, `storage.Client()` envoie tout au faux serveur, et n'a besoin d'aucune clé. Tes scripts `charger_gcs.py` et compagnie marchent donc tels quels.

Ce qui ne marche pas avec lui : la console web de Google, les commandes `gsutil` et `gcloud storage`, et tout ce qui est exécuté chez Google (tables externes, Dataproc). Pour voir le contenu d'un bucket, tu demandes à l'API avec `curl`.

~~~hcl
terraform {
  required_providers {
    google = { source = "hashicorp/google", version = "~> 6.0" }
  }
}

# Le vrai Google Cloud, pour BigQuery (le bac à sable)
provider "google" {
  credentials = file(pathexpand(var.credentials))
  project     = var.project
}

# Le faux Cloud Storage de ton Codespace : même provider, autre adresse
provider "google" {
  alias                   = "local"
  project                 = var.project
  access_token            = "pas-de-cle" # le faux serveur ne vérifie rien
  storage_custom_endpoint = var.gcs_emulator
}

resource "google_storage_bucket" "lake" {
  provider      = google.local
  name          = "${var.project}-dez-lake"
  location      = var.location
  force_destroy = true
}

resource "google_bigquery_dataset" "dataset" {
  dataset_id = var.bq_dataset_name
  location   = var.location
  # Les durées imposées par le bac à sable (60 jours), écrites ici :
  # sinon Terraform verrait une différence à chaque plan
  default_table_expiration_ms     = 5184000000
  default_partition_expiration_ms = 5184000000
}
~~~

`vers_bigquery.py`, le pont entre ton lac et BigQuery. Tu le réutilises aux modules 2 et 3 et dans ton projet : garde-le.

~~~python
"""Le pont entre ton lac (le faux Cloud Storage) et ton entrepôt (le bac à sable BigQuery).

Usage, depuis le dossier du script :
    uv run python vers_bigquery.py <préfixe dans le bucket> <dataset.table>
Exemple :
    uv run python vers_bigquery.py green/ dez_dataset.green_2019_2020
"""
import gzip
import os
import shutil
import sys
import tempfile

from google.api_core.exceptions import NotFound
from google.cloud import bigquery, storage

if len(sys.argv) != 3:
    sys.exit("Usage : uv run python vers_bigquery.py <préfixe> <dataset.table>")
prefixe, table = sys.argv[1], sys.argv[2]

bucket_name = os.environ.get("GCP_BUCKET")
if not bucket_name:
    sys.exit("Définis d'abord GCP_BUCKET, par exemple : export GCP_BUCKET=dez-local-dez-lake")
# Sans cette variable, la bibliothèque parlerait au vrai Cloud Storage, que tu n'as pas
if not os.environ.get("STORAGE_EMULATOR_HOST"):
    sys.exit("Définis d'abord STORAGE_EMULATOR_HOST=http://localhost:4443 (leçon 01-14)")

lac = storage.Client(project="dez-local")  # le faux Cloud Storage : aucune clé
bq = bigquery.Client()                      # le vrai BigQuery : ta clé (GOOGLE_APPLICATION_CREDENTIALS)

fichiers = sorted(b.name for b in lac.list_blobs(bucket_name, prefix=prefixe) if not b.name.endswith("/"))
if not fichiers:
    sys.exit(f"Aucun fichier sous gs://{bucket_name}/{prefixe}")

# Un CSV n'a pas de types : on reprend ceux de la table, que tu as créée vide avec CREATE TABLE
schema_csv = None
if any(".csv" in f for f in fichiers):
    try:
        schema_csv = bq.get_table(table).schema
    except NotFound:
        sys.exit(f"Pour des CSV, crée d'abord la table vide avec ses colonnes : CREATE TABLE {table} (...)")

premier = True
for nom in fichiers:
    if nom.endswith(".parquet"):
        config = bigquery.LoadJobConfig(source_format=bigquery.SourceFormat.PARQUET)
    elif nom.endswith((".csv", ".csv.gz")):
        config = bigquery.LoadJobConfig(source_format=bigquery.SourceFormat.CSV,
                                        skip_leading_rows=1, schema=schema_csv)
    else:
        print(f"ignoré : {nom}")
        continue
    # Le premier fichier remplace le contenu, les suivants s'ajoutent :
    # relancer le script redonne la même table, sans doublons
    config.write_disposition = "WRITE_TRUNCATE" if premier else "WRITE_APPEND"
    with tempfile.TemporaryDirectory() as tmp:
        local = os.path.join(tmp, "fichier")
        lac.bucket(bucket_name).blob(nom).download_to_filename(local)
        if nom.endswith(".gz"):  # on décompresse avant l'envoi : plus simple et plus sûr
            with gzip.open(local, "rb") as src, open(local + ".csv", "wb") as dst:
                shutil.copyfileobj(src, dst)
            local += ".csv"
        with open(local, "rb") as f:
            job = bq.load_table_from_file(f, table, job_config=config)
        job.result()  # attend la fin ; lève l'erreur de BigQuery s'il refuse le fichier
    premier = False
    print(f"chargé : {nom} ({job.output_rows} lignes)")

print(f"{table} : {bq.get_table(table).num_rows} lignes en tout")
~~~
