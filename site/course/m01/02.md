@@ brief
- Un **pipeline de données** prend des données en entrée, les transforme et les écrit ailleurs (fichier Parquet, base de données…).
- 🔑 On ne fait pas `pip install` au niveau du système : chaque projet a son **environnement virtuel**, avec ses propres versions de paquets.
- **uv** gère le projet : `uv init` crée `pyproject.toml`, `uv add` ajoute un paquet, `uv run` lance une commande dans l'environnement.
- 🔑 `uv.lock` fige les versions exactes : c'est lui qui rend l'installation reproductible.
- Les fichiers produits (`*.parquet`) vont dans `.gitignore`.

@@ predict
Après `uv init` et `uv add pandas pyarrow`, tu lances `python pipeline.py 10`, **sans** `uv run`. Que se passe-t-il ?

@@ predict-answer
Le plus souvent : `ModuleNotFoundError: No module named 'pandas'`. Le `python` du système ne voit pas les paquets installés dans le `.venv` du projet. `uv run python pipeline.py 10` marche, parce que `uv run` utilise le Python du `.venv`. Si ça marche quand même sans `uv run`, c'est que pandas est installé globalement : compare `which python` et `uv run which python`.

@@ constraints
- Projet créé avec uv, en Python 3.13, avec pandas et pyarrow comme dépendances
- `pipeline.py` reçoit un mois entre 1 et 12 en argument, et écrit un fichier `output_month_<mois>.parquet` qui contient un petit DataFrame d'au moins 3 colonnes

@@ guide
### 1. Crée le projet avec uv

**uv** gère les projets Python : la version de Python, les bibliothèques (pandas…) et un environnement isolé pour le projet.

~~~bash
mkdir -p /workspaces/data-engineering-zoomcamp/mon-travail/module-01/pipeline
cd /workspaces/data-engineering-zoomcamp/mon-travail/module-01/pipeline
uv init --python=3.13
~~~

`ls -a` montre ce que uv a créé : `pyproject.toml` (la fiche du projet), `.python-version`, `main.py` et `README.md`.

### 2. Ajoute les bibliothèques

`uv add` suivi des noms installe des bibliothèques et les note dans `pyproject.toml`. Ajoute `pandas` et `pyarrow` (pyarrow sert à écrire les fichiers Parquet). Deux choses apparaissent : `.venv/`, l'environnement avec les bibliothèques installées, et `uv.lock`, la liste exacte des versions installées.

### 3. Lis les arguments d'un script

Crée un petit fichier d'essai `essai.py` :

~~~python
import sys
print(sys.argv)
~~~

Lance `uv run python essai.py bonjour 42`. Il affiche `['essai.py', 'bonjour', '42']` : `sys.argv` est la liste de ce que tu as tapé après `python`, et ce sont toujours des **textes**, même `'42'`. `int("42")` le transforme en nombre. Supprime `essai.py` quand tu as compris.

### 4. Écris pipeline.py

Crée `pipeline.py` (`code pipeline.py`). Dans l'ordre, ton script doit :

1. vérifier qu'il a reçu **un** argument, que c'est un nombre (`"3".isdigit()` vaut `True`), et qu'il est entre 1 et 12 ;
2. sinon, afficher un message qui explique comment l'utiliser, puis `sys.exit(1)` : le script s'arrête avec le code 1, qui veut dire « erreur » ;
3. créer un petit DataFrame. Exemple de forme : `pd.DataFrame({"jour": [1, 2, 3], "ventes": [10, 4, 7]})` crée un tableau de deux colonnes et trois lignes. Toi, il en faut au moins trois, dont une avec le mois ;
4. l'écrire avec `df.to_parquet("…")`, sous le nom `output_month_<mois>.parquet`. En Python, `f"output_month_{month}.parquet"` insère la valeur de `month` dans le texte.

### 5. Teste les deux cas

`echo $?` affiche le code de sortie de la commande d'avant : 0 si tout va bien.

~~~bash
uv run python pipeline.py 3 ; echo $?
uv run python pipeline.py 13 ; echo $?
~~~

Tu dois voir `0` puis `1`, et un fichier `output_month_3.parquet` dans le dossier.

### 6. Le Parquet ignoré, uv.lock commité

Ajoute `*.parquet` au `.gitignore` du dossier : `echo "*.parquet" >> .gitignore` (`>>` ajoute une ligne sans effacer). Puis `git status` : tu dois voir `pipeline.py`, `pyproject.toml`, `uv.lock`, mais aucun `.parquet` ni `.venv`. Commite.

@@ hints
- `sys.argv` est la liste des arguments : `sys.argv[0]` est le nom du script.
- `sys.exit(1)` termine le script avec le code 1. Après une commande, `echo $?` affiche le code de sortie de la commande précédente.
- `uv init --python=3.13` puis `uv add pandas pyarrow`. Vérifie que `uv.lock` est apparu : tu en auras besoin dans la leçon suivante.

@@ solution
~~~python
import sys
import pandas as pd

# sys.argv = ["pipeline.py", "<mois>"] : il faut exactement un argument,
# composé de chiffres, entre 1 et 12. Sinon : message d'aide et code de sortie 1.
if len(sys.argv) != 2 or not sys.argv[1].isdigit() or not 1 <= int(sys.argv[1]) <= 12:
    print("Usage : python pipeline.py <mois entre 1 et 12>")
    sys.exit(1)

month = int(sys.argv[1])                    # le texte "3" devient le nombre 3
df = pd.DataFrame({                         # 3 colonnes, 3 lignes
    "day": [1, 2, 3],
    "month": [month] * 3,                   # [3] * 3 donne [3, 3, 3]
    "trips": [120, 98, 143],
})
print(df)
df.to_parquet(f"output_month_{month}.parquet")
print(f"Pipeline terminé pour le mois {month}")
~~~

@@ breakfix
Supprime le dossier `.venv`, puis relance `uv run python pipeline.py 3`. Que fait uv ? Ensuite, dans `pyproject.toml`, remplace la ligne de pandas par `"pandas==0.0.1"` et relance. Lis l'erreur et répare.

@@ breakfix-hints
- La première fois, uv ne plante pas : regarde bien ce qu'il affiche avant de lancer le script.
- La deuxième erreur vient de la **résolution** des dépendances : uv cherche une version qui n'existe pas.
- Pour réparer, remets une contrainte raisonnable, ou utilise `uv add pandas` qui choisit une version valide et met à jour `uv.lock`.

@@ breakfix-answer
Sans `.venv`, uv **recrée** l'environnement à partir de `uv.lock`, avec exactement les mêmes versions : c'est la reproductibilité. Avec `pandas==0.0.1`, uv ne trouve aucune version qui correspond et refuse d'installer quoi que ce soit. Lire une erreur de résolution de dépendances est un réflexe quotidien en data engineering.

@@ cles
- Environnement virtuel | environnement virtuel python venv | Chaque projet garde ses propres versions de paquets. Sans ça, deux projets qui veulent deux versions de pandas se cassent l'un l'autre.
- uv, `pyproject.toml` et `uv.lock` | uv python gestionnaire de paquets uv.lock | `uv.lock` fige les versions exactes : c'est lui qui permet de réinstaller le même projet ailleurs, dans ton image Docker à la leçon 3 par exemple.
