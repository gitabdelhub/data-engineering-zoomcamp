@@ brief
- Le jeu de données : les **trajets des taxis jaunes de New York**, janvier 2021, au format CSV compressé (`.csv.gz`). pandas le lit directement depuis l'URL.
- On précise les **types** des colonnes (`dtype`) et les colonnes de **dates** (`parse_dates`), sinon pandas devine mal.
- SQLAlchemy relie pandas à Postgres : `create_engine('postgresql+psycopg://user:mdp@host:port/base')`.
- `df.head(0).to_sql(..., if_exists='replace')` crée la table vide, puis `to_sql(..., if_exists='append')` ajoute les lignes.
- On lit le fichier **par morceaux** (`chunksize=100000`) pour ne pas remplir la mémoire. `tqdm` affiche une barre de progression.

@@ predict
Le fichier de janvier 2021 contient environ 1,37 million de lignes. Avec `chunksize=100000`, combien de fois la boucle tourne-t-elle ? Et si le script plante pendant le 5ᵉ morceau, que contient la table ?

@@ predict-answer
**14 fois** : 13 morceaux de 100 000 lignes, puis un dernier plus petit. Si le script plante au 5ᵉ morceau, la table contient les **4 premiers** morceaux, soit 400 000 lignes : chaque `to_sql` est enregistré séparément. Une table à moitié remplie est un vrai problème en production : c'est pour ça qu'on veut des pipelines qu'on peut relancer sans risque.

@@ solution
~~~python
import pandas as pd
from sqlalchemy import create_engine

engine = create_engine("postgresql+psycopg://root:root@localhost:5432/ny_taxi")
url = "https://github.com/DataTalksClub/nyc-tlc-data/releases/download/misc/taxi_zone_lookup.csv"

df_zones = pd.read_csv(url)
df_zones.to_sql(name="zones", con=engine, if_exists="replace", index=False)
print(len(df_zones))   # 265
~~~

@@ breakfix-answer
Avec seulement des `append`, la deuxième exécution **double** les lignes : 600 000 au lieu de 300 000. La leçon commence par recréer la table vide (`replace`) : relancer donne donc toujours le même résultat. Cette propriété s'appelle l'**idempotence**, et c'est l'une des règles les plus importantes d'un pipeline de données.
