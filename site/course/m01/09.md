@@ brief
- 🔑 **Docker Compose** lance plusieurs conteneurs depuis un seul fichier YAML (`docker-compose.yaml`), au lieu de longues commandes `docker run`.
- 🔑 Chaque **service** devient un conteneur. Compose crée tout seul un **réseau** commun, où chaque service est joignable par son nom.
- 🔑 `docker compose up` (ou `-d` en arrière-plan), `docker compose down` pour tout arrêter, `down -v` pour supprimer aussi les volumes.
- Le réseau créé porte le nom du dossier suivi de `_default`.

@@ codespaces
- Utilise `docker compose` **avec un espace** (Compose version 2). La leçon écrit `docker-compose` avec un tiret : c'est l'ancienne commande, qui peut ne pas exister dans ton Codespace.
- Arrête d'abord les conteneurs des leçons 7 et 8 (`docker stop db pgadmin`) : sinon les ports 5432 et 8085 sont déjà pris.

@@ predict
Tu lances `docker compose up` dans le dossier `mon-travail/module-01/compose/`. Quel est le nom du réseau créé ? Et après `docker compose down`, tes données Postgres sont-elles perdues ?

@@ predict-answer
Le réseau s'appelle **`compose_default`** : le nom du dossier, puis `_default`. Après `docker compose down`, les conteneurs et le réseau sont supprimés, mais **les volumes nommés restent** : tes données sont gardées. Seul `docker compose down -v` les supprime.

@@ guide
### 1. Un dossier pour la compose

~~~bash
mkdir -p /workspaces/data-engineering-zoomcamp/mon-travail/module-01/compose
cd /workspaces/data-engineering-zoomcamp/mon-travail/module-01/compose
~~~

Arrête les conteneurs des leçons 7 et 8 (`docker stop db pgadmin`) : ils occupent les ports 5432 et 8085.

### 2. Traduis un docker run en service

Un fichier `docker-compose.yaml` décrit plusieurs conteneurs. Chaque option de `docker run` a sa clé YAML. Exemple :

~~~bash
docker run -d --name web -e MODE=prod -p 8000:80 -v web_data:/data nginx
~~~

devient :

~~~yaml
services:
  web:
    image: nginx
    environment:
      MODE: prod
    ports:
      - "8000:80"
    volumes:
      - web_data:/data

volumes:
  web_data:
~~~

Pas besoin de réseau : Compose en crée un pour tous les services du fichier, et chacun s'appelle par **le nom de son service**.

### 3. Écris pgdatabase et pgadmin

Traduis tes deux `docker run` de la leçon 7 en deux services, `pgdatabase` et `pgadmin`. Les volumes nommés se déclarent aussi tout en bas, sous `volumes:`.

### 4. Les mots de passe dans .env

Crée un fichier `.env` à côté de la compose, une variable par ligne : `PG_USER=root`, etc. Dans le YAML, écris `${PG_USER}` à la place de la valeur : Compose la remplace tout seul. Ajoute `.env` au `.gitignore` du dossier.

### 5. Le service ingest

Au lieu de `image:`, ce service a `build:` avec le chemin du dossier qui contient ton Dockerfile : `../pipeline`. Les options du script vont dans `command:`. `--pg-host` vaut maintenant `pgdatabase`, le nom du service.

### 6. Attendre que Postgres soit prêt

Problème : Postgres met quelques secondes à accepter des connexions, et `ingest` démarre trop tôt. Deux pièces règlent ça :

- un `healthcheck` sur `pgdatabase` : une commande que Docker lance régulièrement pour savoir si le service va bien. Ici, `pg_isready`, qui répond OK quand Postgres accepte les connexions ;
- dans `ingest`, `depends_on` en forme longue, avec `condition: service_healthy`.

Les hints montrent où chercher la forme exacte.

### 7. Lance tout

`docker compose up` : les trois services démarrent. Les logs défilent avec le nom de chaque service, et `ingest` finit par `exited with code 0`. **Ctrl + C** arrête tout. `docker compose down` supprime les conteneurs, mais garde les volumes.

Vérifie dans pgAdmin (enregistre le serveur avec Host `pgdatabase`) : `green_taxi_trips` contient 76 518 lignes.

@@ hints
- Pour construire une image depuis un dossier, un service utilise `build:` au lieu de `image:`. Les options du script vont dans `command:`.
- Cherche `healthcheck` dans la documentation de Compose, et la forme longue de `depends_on` avec `condition: service_healthy`. La commande `pg_isready` est incluse dans l'image postgres.
- Compose lit tout seul un fichier `.env` placé à côté du compose, et remplace les `${VARIABLE}` du YAML.

@@ solution
~~~yaml
services:
  pgdatabase:
    image: postgres:18
    environment:
      POSTGRES_USER: ${PG_USER}
      POSTGRES_PASSWORD: ${PG_PASS}
      POSTGRES_DB: ny_taxi
    volumes:
      - ny_taxi_postgres_data:/var/lib/postgresql
    ports:
      - "5432:5432"
    healthcheck:                # « prêt » = pg_isready répond OK
      test: ["CMD-SHELL", "pg_isready -U ${PG_USER} -d ny_taxi"]
      interval: 5s
      retries: 10

  pgadmin:
    image: dpage/pgadmin4
    environment:
      PGADMIN_DEFAULT_EMAIL: ${PGADMIN_EMAIL}
      PGADMIN_DEFAULT_PASSWORD: ${PGADMIN_PASS}
    volumes:
      - pgadmin_data:/var/lib/pgadmin
    ports:
      - "8085:80"

  ingest:
    build: ../pipeline          # ton Dockerfile de la leçon 8
    command: >
      --color=green --year=2021 --month=1
      --pg-user=${PG_USER} --pg-pass=${PG_PASS}
      --pg-host=pgdatabase --pg-port=5432 --pg-db=ny_taxi
    depends_on:                 # démarre seulement quand pgdatabase est « healthy »
      pgdatabase:
        condition: service_healthy

volumes:
  ny_taxi_postgres_data:
  pgadmin_data:
~~~
`.env` (à ajouter au `.gitignore`) :
~~~text
PG_USER=root
PG_PASS=root
PGADMIN_EMAIL=admin@admin.com
PGADMIN_PASS=root
~~~

@@ breakfix
Dans ton compose, change le port de pgAdmin en `"5432:80"`, puis `docker compose up`. Lis l'erreur, explique-la, puis répare.

@@ breakfix-hints
- L'erreur ne vient pas de pgAdmin : elle vient de Docker, au moment de publier le port.
- Deux services de ton compose essaient d'utiliser le même port **de ton Codespace**.
- À gauche des deux-points, le port de ton Codespace ; à droite, celui du conteneur.

@@ breakfix-answer
Docker refuse avec un message du type `Bind for 0.0.0.0:5432 failed: port is already allocated`. Le port 5432 de ton Codespace est déjà pris par Postgres : deux conteneurs ne peuvent pas publier le même port. Le port **dans** le conteneur (80) n'a rien à voir : seul le côté gauche compte pour les conflits.

@@ pas
>>> services:
**Ce que « Here's the docker-compose.yaml file » veut dire :** crée un fichier `docker-compose.yaml` dans ton dossier `pipeline` et mets-y ce contenu.

~~~bash
cd /workspaces/data-engineering-zoomcamp/mon-travail/module-01/pipeline
code docker-compose.yaml
~~~

Colle, puis **Ctrl + S**. En YAML, **les espaces au début des lignes sont le sens du fichier** : 2 espaces par niveau, jamais de tabulation. Si un niveau est décalé, `docker compose` répond une erreur du type `yaml: line 5: mapping values are not allowed`.

**Ce que le texte ne dit pas, et qui compte :** Compose ajoute le **nom du dossier** devant ce qu'il crée. Ton dossier s'appelle `pipeline`, donc :

| Dans le fichier | Ce que Docker crée vraiment |
| --- | --- |
| volume `ny_taxi_postgres_data` | `pipeline_ny_taxi_postgres_data` |
| volume `pgadmin_data` | `pipeline_pgadmin_data` |
| le réseau automatique | `pipeline_default` |

Conséquence : c'est un **nouveau** volume, **vide**. Tes tables des leçons 5 à 8 sont dans l'ancien volume `ny_taxi_postgres_data`, que Compose n'utilise pas. Ta base sera donc vide au premier lancement, et pgAdmin te redemandera de créer le serveur. Le dernier bloc de la leçon recharge les trajets.

>>> docker-compose up
**Tape `docker compose up`, avec un espace.** `docker-compose` avec un tiret est l'ancienne commande, qui peut ne pas exister dans ton Codespace (`command not found`). Pareil pour toutes les commandes de cette leçon.

**Avant, « Make sure that all previous containers aren't running » :**

1. Ctrl + C dans les terminaux où tournent Postgres et pgAdmin (leçon 7).
2. `docker ps` ne doit plus montrer `pgdatabase` ni `pgadmin`. Sinon : `docker stop pgdatabase pgadmin`.

**D'où taper :** depuis `pipeline`, là où est `docker-compose.yaml`. Compose cherche ce fichier dans le dossier où tu es.

**Ce que tu dois voir :** `Network pipeline_default Created`, `Volume ... Created`, puis les logs des deux services mélangés, chaque ligne précédée de son nom (`pgdatabase-1 |`, `pgadmin-1 |`). Le terminal reste occupé, comme avec `docker run -it`.

>>> docker-compose up -d
**Avant :** si les services tournent déjà au premier plan, fais Ctrl + C pour les arrêter. Puis tape `docker compose up -d`.

**Ce que tu dois voir :** deux lignes `Container pipeline-pgdatabase-1 Started` et `Container pipeline-pgadmin-1 Started`, puis l'invite `$` revient tout de suite. Les services tournent **en arrière-plan** (`-d` = detached). `docker compose ps` les montre avec l'état `running`.

>>> docker-compose down
**D'où taper :** depuis `pipeline`. Tape `docker compose down`.

**Ce que tu dois voir :** les conteneurs puis le réseau `Removed`. Les **volumes restent** : tes données ne sont pas effacées. Le prochain `docker compose up -d` les retrouve.

>>> docker-compose logs
**Tape les commandes avec un espace :** `docker compose logs`, depuis `pipeline`. Utile quand les services tournent en arrière-plan : c'est la seule façon de voir leurs messages. `docker compose logs pgadmin` montre un seul service, et `docker compose logs -f` suit les nouveaux messages en direct (Ctrl + C pour arrêter de suivre, les services continuent).

**Attention à `docker compose down -v` :** le `-v` **supprime les volumes**, donc toute ta base et la configuration de pgAdmin. Ne la tape que si tu veux vraiment repartir de zéro.

>>> --network=pipeline_default
**Avant :** les services tournent en arrière-plan (`docker compose up -d`) et ton image `taxi_ingest:v001` existe (leçon 8, `docker images`).

1. `docker network ls` : cherche la ligne `pipeline_default`. Si ton dossier avait un autre nom, le réseau s'appelle `<nom du dossier>_default` : mets ce nom dans `--network`.
2. Lance la commande `docker run` du bloc, d'un seul coup (les lignes `#` sont des commentaires). `--pg-host=pgdatabase` marche parce que Compose donne à chaque service son nom du fichier sur le réseau.
3. Tu dois voir la barre de tqdm, puis l'invite revient.

**Vérifie dans pgAdmin :** ouvre-le par l'onglet **Ports**, ligne 8085. Le volume pgAdmin est nouveau, donc il faut recréer le serveur, comme à la leçon 7 : Host `pgdatabase`, Port `5432`, Username `root`, Password `root`. Puis `SELECT COUNT(1) FROM yellow_taxi_trips;` doit donner `1369765`.
