@@ brief
- On met le script d'ingestion dans une image Docker, avec le même schéma de Dockerfile qu'à la leçon 3 (uv, `uv.lock`, `ENTRYPOINT`).
- Les options du script se passent **après** le nom de l'image : `docker run ... taxi_ingest:v001 --pg-host=...`.
- Le conteneur d'ingestion doit être sur le **même réseau** que Postgres, et `--pg-host` est le **nom du conteneur** Postgres.

@@ codespaces
- Construis l'image depuis ton dossier `mon-travail/module-01/pipeline/`, pas depuis le dossier officiel.
- Ton Postgres et ton réseau de la leçon 7 (`db` sur `dez-net`) doivent tourner.

@@ verified
- Le dossier officiel `01-docker-terraform/pipeline/` ne contient pas de `uv.lock`, alors que son Dockerfile le copie. Et son script utilise `postgresql+psycopg://` alors que son `pyproject.toml` installe `psycopg2-binary`. Ces deux défauts sont l'exercice « Casser et réparer » de cette leçon.

@@ predict
Le conteneur d'ingestion se connecte à Postgres. Pourquoi `--pg-host=pgdatabase` et pas `localhost` ? Et quel port : celui du conteneur Postgres, ou celui publié sur ton Codespace ?

@@ predict-answer
Sur un réseau Docker, un conteneur en joint un autre par son **nom**. `localhost` serait le conteneur d'ingestion lui-même. Le port est celui **du conteneur** Postgres (5432), car la connexion passe par le réseau Docker, pas par ton Codespace. Le port publié avec `-p` ne sert qu'aux programmes qui tournent dans ton Codespace, comme pgcli.

@@ practice
Dockerise **ton** script d'ingestion de la leçon 6 (avec `--color`) et charge les taxis verts avec le conteneur.

@@ constraints
- L'image s'appelle `taxi_ingest:v001` et se construit depuis `mon-travail/module-01/pipeline/`
- Le dossier `.venv` et les fichiers de données ne sont **pas copiés** dans l'image
- Le conteneur est supprimé à la fin, et il charge `green_taxi_trips` (janvier 2021) dans ta base `db` sur le réseau `dez-net`
- Les dépendances de développement (jupyter, pgcli) ne sont pas installées dans l'image

@@ hints
- Un fichier `.dockerignore`, à côté du Dockerfile, marche comme un `.gitignore` pour `COPY`.
- `uv sync` a une option pour ne pas installer les groupes de développement. Regarde `uv sync --help`.
- Mets `--network` et `--rm` **avant** le nom de l'image, et les options du script **après**.

@@ solution
~~~dockerfile
FROM python:3.13-slim
COPY --from=ghcr.io/astral-sh/uv:latest /uv /bin/

WORKDIR /code
ENV PATH="/code/.venv/bin:$PATH"

COPY pyproject.toml .python-version uv.lock ./
RUN uv sync --locked --no-dev

COPY ingest_data.py .
ENTRYPOINT ["python", "ingest_data.py"]
~~~
`.dockerignore` :
~~~text
.venv/
*.parquet
*.csv.gz
*.ipynb
~~~
~~~bash
docker build -t taxi_ingest:v001 .
docker run -it --rm --network=dez-net taxi_ingest:v001 \
  --color=green --year=2021 --month=1 \
  --pg-user=root --pg-pass=root --pg-host=db --pg-port=5432 --pg-db=ny_taxi
~~~

@@ breakfix
Essaie de construire l'image du dossier **officiel**, sans le modifier : `docker build -t officiel:test 01-docker-terraform/pipeline`. Ça échoue. Copie le dossier dans `mon-travail/module-01/officiel/` et répare-le **dans la copie** jusqu'à ce que le conteneur charge des données. Il y a deux problèmes, l'un après l'autre.

@@ breakfix-hints
- Le premier échec arrive pendant le build, sur une ligne `COPY`. Quel fichier manque dans le dossier ? Quelle commande uv le crée ?
- Le deuxième échec arrive au lancement : `ModuleNotFoundError`. Compare le début de l'URL dans `create_engine` avec les dépendances de `pyproject.toml`.
- `postgresql+psycopg://` demande la bibliothèque `psycopg` (version 3). `psycopg2-binary` est une autre bibliothèque.

@@ breakfix-answer
1. **Build** : `uv.lock` n'existe pas dans le dossier, donc le `COPY` échoue. `uv lock` dans la copie le génère.
2. **Lancement** : `No module named 'psycopg'`. Le script utilise le pilote psycopg 3, mais le projet installe psycopg2. Il faut aligner les deux : `uv add "psycopg[binary]"` (puis reconstruire), ou bien changer l'URL en `postgresql+psycopg2://`.

Un vrai repo contient souvent ce genre de décalage. Lire l'erreur, trouver la cause, réparer dans **ta** copie : c'est le quotidien. Tu pourrais même le signaler aux auteurs du cours avec une issue.
