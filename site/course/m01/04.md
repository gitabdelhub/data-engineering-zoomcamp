@@ brief
- 🔑 Postgres tourne dans un conteneur, sans rien installer : l'image `postgres:18` se configure avec des **variables d'environnement** (`-e POSTGRES_USER`…).
- 🔑 Un **volume** garde les données quand le conteneur s'arrête. Avec Postgres 18, on le monte sur `/var/lib/postgresql`.
- 🔑 **Volume nommé** (`nom:/chemin`) : géré par Docker. **Bind mount** (`/chemin/hôte:/chemin`) : ton propre dossier.
- 🔑 `-p 5432:5432` publie le port : **à gauche le port de ton Codespace, à droite celui du conteneur**.
- `pgcli` est un client SQL en ligne de commande, installé comme dépendance de développement (`uv add --dev`).

@@ codespaces

@@ predict
Tu lances Postgres **sans** l'option `-v`, tu crées une table, tu arrêtes le conteneur et tu en relances un nouveau avec la même commande. Ta table existe-t-elle encore ? Pourquoi ?

@@ predict-answer
**Non.** Sans volume nommé, les données sont écrites dans le conteneur (ou dans un volume anonyme créé pour lui). Un nouveau conteneur repart d'une base vide. C'est la même règle qu'à la leçon 1 : un conteneur oublie tout, sauf ce qui passe par un volume que tu réutilises.

@@ guide
### 1. Lis la commande de la leçon, option par option

La leçon lance Postgres avec `docker run`. Les options nouvelles :

| Option | Ce qu'elle fait |
| --- | --- |
| `-e NOM="valeur"` | une **variable d'environnement** : l'image Postgres lit `POSTGRES_USER`, `POSTGRES_PASSWORD` et `POSTGRES_DB` pour créer l'utilisateur et la base |
| `-v nom:/var/lib/postgresql` | un **volume nommé** : Docker range les données dans un espace à lui, appelé `nom`, qui survit au conteneur |
| `-p 5432:5432` | publie le port : `port du Codespace:port du conteneur` |
| `-d` | lance le conteneur **en arrière-plan** : ton terminal reste libre |
| `--name pg` | donne un nom au conteneur, pour le retrouver facilement |

### 2. Lance ta base

Écris ta commande avec : `-d`, `--name pg`, les trois variables (`dez`, `dez`, `ny_taxi`), le volume `dez_pgdata` sur `/var/lib/postgresql`, le port 5432, et l'image `postgres:18` en dernier. Docker répond par un long identifiant : le conteneur tourne. Vérifie avec `docker ps`, et lis ses messages avec `docker logs pg`.

### 3. Connecte-toi avec pgcli

pgcli est un client SQL dans le terminal. Va dans ton projet de la leçon 2 (`cd /workspaces/data-engineering-zoomcamp/mon-travail/module-01/pipeline`) et, si ce n'est pas déjà fait, installe-le avec `uv add --dev pgcli`. Puis :

~~~bash
uv run pgcli -h localhost -p 5432 -u dez -d ny_taxi
~~~

`-h` est la machine, `-p` le port, `-u` l'utilisateur et `-d` la base. pgcli demande le mot de passe : `dez`.

### 4. Crée une table et une ligne

Dans pgcli, une commande SQL finit par `;`. Exemple sur une autre table :

~~~sql
CREATE TABLE fruits (id INTEGER, nom VARCHAR(30));
INSERT INTO fruits VALUES (1, 'pomme');
SELECT * FROM fruits;
~~~

Fais la même chose avec une table `essai`. `\dt` liste les tables, et `\q` quitte pgcli.

### 5. Supprime le conteneur, garde le volume

`docker stop pg` arrête le conteneur, `docker rm pg` le supprime. `docker ps -a` ne le montre plus. Le volume, lui, existe toujours : `docker volume ls` affiche `dez_pgdata`.

### 6. Relance et vérifie

Relance **exactement** la même commande qu'à l'étape 2 (la flèche ↑ du clavier la retrouve). Reconnecte-toi avec pgcli et lis ta table `essai` : ta ligne est toujours là, parce que les données sont dans le volume et pas dans le conteneur.

@@ hints
- L'option pour l'arrière-plan est `-d` (detached). Les logs restent visibles avec `docker logs pg`.
- `--name` donne un nom au conteneur. Pour le supprimer : `docker stop pg` puis `docker rm pg`.
- pgcli : `uv run pgcli -h localhost -p 5432 -u dez -d ny_taxi`. Dans pgcli, `\dt` liste les tables.

@@ solution
~~~bash
# Postgres en arrière-plan (-d), nommé pg, données dans le volume dez_pgdata
docker run -d \
  --name pg \
  -e POSTGRES_USER="dez" \
  -e POSTGRES_PASSWORD="dez" \
  -e POSTGRES_DB="ny_taxi" \
  -v dez_pgdata:/var/lib/postgresql \
  -p 5432:5432 \
  postgres:18

# Se connecter (mot de passe : dez), créer la table et une ligne
uv run pgcli -h localhost -p 5432 -u dez -d ny_taxi
# CREATE TABLE essai (id INTEGER, txt VARCHAR(50));
# INSERT INTO essai VALUES (1, 'je survis');
# \q

# Supprimer le conteneur : le volume dez_pgdata reste
docker stop pg && docker rm pg
# Relancer la même commande docker run, puis vérifier que la ligne a survécu :
uv run pgcli -h localhost -p 5432 -u dez -d ny_taxi
# SELECT * FROM essai;
~~~

Personne n'écoute sur 5432 de ton côté, donc la connexion est refusée. La réparation : `uv run pgcli -h localhost -p 5433 -u dez -d ny_taxi`. Tu en auras besoin au homework (question 2).

@@ zoom
### `-p 5432:5432` : ouvrir une porte vers le conteneur

Un conteneur a son propre réseau. Postgres écoute sur le port 5432 **à l'intérieur** du conteneur, et rien dehors ne peut le joindre. `-p` ouvre une porte : à gauche le port de ton Codespace, à droite celui du conteneur. Avec `-p 5433:5432`, Postgres écoute toujours sur 5432 dans le conteneur, mais tu le joins par `localhost:5433` depuis ton Codespace. C'est utile quand le 5432 est déjà pris par une autre base.

### Volume nommé ou bind mount

| | Volume nommé : `-v dez_pgdata:/var/lib/postgresql` | Bind mount : `-v $(pwd)/data:/var/lib/postgresql` |
| --- | --- | --- |
| Où sont les fichiers | Dans un espace géré par Docker | Dans **ton** dossier |
| Pour les voir | `docker volume ls`, `docker volume inspect` | `ls data` |
| Bien pour | Les données d'une base : Docker gère les droits | Ton code, tes fichiers d'entrée et de sortie |

Ce qui les distingue dans la commande : un `/` au début du côté gauche, c'est un chemin, donc un bind mount. Sans `/`, c'est un nom, donc un volume nommé.

### Les variables d'environnement

`-e POSTGRES_USER="dez"` donne une valeur au programme du conteneur, sans modifier l'image. L'image Postgres lit ses variables **au premier démarrage seulement**, quand le volume est vide, pour créer l'utilisateur et la base. Change le mot de passe plus tard avec le même volume : rien ne change, la base existe déjà. Pour repartir de zéro, il faut supprimer le volume (`docker volume rm`), donc les données.

>>> CREATE TABLE test
**Où taper :** dans pgcli, invite `root@localhost:ny_taxi>`. **Une commande à la fois**, puis Entrée. Les lignes qui commencent par `--` sont des commentaires : ne les tape pas.

| Tu tapes | Tu dois voir |
| --- | --- |
| `\dt` | rien, ou une liste vide : la base n'a encore aucune table |
| `CREATE TABLE test (id INTEGER, name VARCHAR(50));` | `CREATE TABLE` |
| `INSERT INTO test VALUES (1, 'Hello Docker');` | `INSERT 0 1` (1 ligne ajoutée) |
| `SELECT * FROM test;` | un tableau avec `1` et `Hello Docker` |
| `\dt` | cette fois, la table `test` apparaît |
| `\q` | tu sors de pgcli et retrouves l'invite `$` |

Les commandes SQL finissent par `;`. Les commandes qui commencent par `\` sont propres à Postgres (`\dt` = liste des tables, `\q` = quitter) et n'en ont pas besoin. Si un résultat long s'affiche en plein écran, appuie sur `q` pour revenir.

La table `test` reste dans le volume même si tu arrêtes Postgres. Elle ne gêne pas la suite.
