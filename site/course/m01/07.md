@@ brief
- **pgAdmin** est une interface web pour gérer Postgres, plus confortable que pgcli pour les requêtes longues.
- Il tourne dans son propre conteneur (`dpage/pgadmin4`), avec un e-mail et un mot de passe de connexion, publié sur le port 8085.
- Deux conteneurs ne se voient pas par défaut. On crée un **réseau Docker** (`docker network create`) et on y lance les deux, avec `--network` et `--name`.
- Dans pgAdmin, l'hôte de la base est le **nom du conteneur** Postgres (`pgdatabase`), pas `localhost`.

@@ codespaces
- Pour ouvrir pgAdmin : dans l'onglet **Ports**, ligne 8085, clique sur le globe. Dans Chrome, l'adresse est du type `https://<nom>-8085.app.github.dev` ; avec VS Code sur ton PC, `http://localhost:8085` marche directement.
- Le premier démarrage de pgAdmin prend une bonne minute : attends le message `Listening at` dans ses logs.

@@ predict
pgAdmin et Postgres tournent dans deux conteneurs. Dans pgAdmin, tu enregistres le serveur avec Host = `localhost`. Est-ce que ça marche ? Pourquoi ?

@@ predict-answer
**Non.** Dans un conteneur, `localhost` désigne **le conteneur lui-même**, donc pgAdmin se cherche lui-même. Il faut le nom du conteneur Postgres, et que les deux soient sur le même réseau Docker. Docker a un petit DNS interne qui transforme les noms de conteneurs en adresses sur ce réseau.

@@ practice
Relie pgAdmin à Postgres avec **tes propres noms**, différents de ceux de la leçon.

@@ constraints
- Un réseau nommé `dez-net`
- Le conteneur Postgres s'appelle `db` (pas `pgdatabase`), avec le volume de données de la leçon 5 pour retrouver tes tables
- pgAdmin sur le port 8085, avec ton propre e-mail et mot de passe, et ses réglages gardés dans un volume
- Le serveur est enregistré dans pgAdmin, et `SELECT COUNT(*) FROM zones;` marche dans le Query Tool

@@ hints
- Le volume de la leçon 5 s'appelle `ny_taxi_postgres_data` : réutilise-le, avec les mêmes identifiants (`root`) que lorsque la base a été créée.
- Les deux `docker run` ont besoin de `--network=dez-net` et d'un `--name`.
- Dans pgAdmin : clic droit sur Servers, Register, Server. Onglet Connection, Host = le nom du conteneur Postgres.

@@ solution
~~~bash
docker network create dez-net

docker run -d --name db --network=dez-net \
  -e POSTGRES_USER="root" -e POSTGRES_PASSWORD="root" -e POSTGRES_DB="ny_taxi" \
  -v ny_taxi_postgres_data:/var/lib/postgresql \
  -p 5432:5432 postgres:18

docker run -d --name pgadmin --network=dez-net \
  -e PGADMIN_DEFAULT_EMAIL="moi@exemple.com" -e PGADMIN_DEFAULT_PASSWORD="motdepasse" \
  -v pgadmin_data:/var/lib/pgadmin \
  -p 8085:80 dpage/pgadmin4
~~~
Dans pgAdmin : Host `db`, Port `5432`, Username `root`, Password `root`.

@@ selfcheck
- Le Query Tool de pgAdmin renvoie 265 pour `SELECT COUNT(*) FROM zones;`
- Après un redémarrage du conteneur pgAdmin, le serveur enregistré est toujours là
- Le Host du serveur dans pgAdmin est `db`

@@ breakfix
Supprime le conteneur pgAdmin et relance-le **sans** `--network`. Essaie d'enregistrer le serveur avec Host `db` et lis l'erreur. Ensuite, **sans redémarrer pgAdmin**, connecte-le au réseau avec une commande Docker.

@@ breakfix-hints
- L'erreur dit que le nom `db` est inconnu : pgAdmin n'est pas sur le réseau où ce nom existe.
- La commande `docker network` a une sous-commande pour brancher un conteneur déjà lancé.
- `docker network inspect dez-net` liste les conteneurs branchés sur le réseau.

@@ breakfix-answer
Sans le réseau, le nom `db` ne veut rien dire pour pgAdmin : l'erreur parle d'un nom d'hôte qui ne se résout pas. `docker network connect dez-net pgadmin` branche le conteneur à chaud, et l'enregistrement marche. Docker Compose (leçon 9) fera tout ça pour toi.

@@ explain
Comment deux conteneurs se trouvent-ils sur un réseau Docker ? Pourquoi `localhost` ne marche-t-il pas entre conteneurs ?
