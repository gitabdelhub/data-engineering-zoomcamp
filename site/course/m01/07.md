@@ brief
- **pgAdmin** est une interface web pour gérer Postgres, plus confortable que pgcli pour les requêtes longues.
- Il tourne dans son propre conteneur (`dpage/pgadmin4`), avec un e-mail et un mot de passe de connexion, publié sur le port 8085.
- 🔑 Deux conteneurs ne se voient pas par défaut. On crée un **réseau Docker** (`docker network create`) et on y lance les deux, avec `--network` et `--name`.
- 🔑 Dans pgAdmin, l'hôte de la base est le **nom du conteneur** Postgres (`pgdatabase`), pas `localhost`.

@@ codespaces
- Pour ouvrir pgAdmin : dans l'onglet **Ports**, ligne 8085, clique sur le globe. Dans Chrome, l'adresse est du type `https://<nom>-8085.app.github.dev` ; avec VS Code sur ton PC, `http://localhost:8085` marche directement.
- Le premier démarrage de pgAdmin prend une bonne minute : attends le message `Listening at` dans ses logs.

@@ predict
pgAdmin et Postgres tournent dans deux conteneurs. Dans pgAdmin, tu enregistres le serveur avec Host = `localhost`. Est-ce que ça marche ? Pourquoi ?

@@ predict-answer
**Non.** Dans un conteneur, `localhost` désigne **le conteneur lui-même**, donc pgAdmin se cherche lui-même. Il faut le nom du conteneur Postgres, et que les deux soient sur le même réseau Docker. Docker a un petit DNS interne qui transforme les noms de conteneurs en adresses sur ce réseau.

@@ practice
Relie pgAdmin à Postgres avec **tes propres noms**, différents de ceux de la leçon.

@@ constraints
- Un réseau nommé `dez-net`
- Le conteneur Postgres s'appelle `db` (pas `pgdatabase`), avec le volume de données de la leçon 5 pour retrouver tes tables
- pgAdmin sur le port 8085, avec ton propre e-mail et mot de passe, et ses réglages gardés dans un volume
- Le serveur est enregistré dans pgAdmin, et `SELECT COUNT(*) FROM zones;` marche dans le Query Tool

@@ guide
### 1. Fais le ménage

Si un ancien Postgres tourne encore (celui de la leçon 4 ou 5), il occupe le port 5432. Liste les conteneurs avec `docker ps`, puis arrête et supprime ceux qui gênent : `docker stop <nom>` puis `docker rm <nom>`. Tes données restent dans leurs volumes.

### 2. Crée le réseau

Un **réseau Docker** permet à des conteneurs de se parler **par leur nom**. Exemple : `docker network create mon-reseau`. Crée le tien, `dez-net`, puis vérifie avec `docker network ls`.

### 3. Lance Postgres sur ce réseau

Reprends ta commande Postgres de la leçon 5, avec deux changements :

- ajoute `--network=dez-net` et `--name db` **avant** le nom de l'image ;
- garde le volume `ny_taxi_postgres_data` et les identifiants `root` / `root` : la base a été créée avec eux, et le volume contient tes tables, dont `zones`.

N'oublie pas `-d` pour le lancer en arrière-plan.

### 4. Lance pgAdmin sur le même réseau

pgAdmin est une interface web pour Postgres. Son image est `dpage/pgadmin4`. Il lit deux variables : `PGADMIN_DEFAULT_EMAIL` et `PGADMIN_DEFAULT_PASSWORD`, tes identifiants de connexion à pgAdmin. Il écoute sur le port 80 du conteneur : publie-le sur 8085 avec `-p 8085:80`. Ses réglages vont dans un volume monté sur `/var/lib/pgadmin`. Même réseau, et un nom, par exemple `pgadmin`.

### 5. Ouvre pgAdmin

Onglet **Ports**, globe de la ligne 8085. pgAdmin met une bonne minute à démarrer la première fois : si la page ne répond pas, attends et recharge. Connecte-toi avec ton e-mail et ton mot de passe de l'étape 4.

### 6. Enregistre le serveur

Clic droit sur **Servers**, puis **Register → Server**.

- Onglet **General**, Name : ce que tu veux, par exemple `ny_taxi`.
- Onglet **Connection** : Host `db` (le **nom du conteneur**, pas `localhost`), Port `5432`, Username `root`, Password `root`.

Enregistre. Le serveur apparaît à gauche.

### 7. Lance une requête

Déplie ton serveur jusqu'à la base `ny_taxi`, clic droit, **Query Tool**. Tape `SELECT COUNT(*) FROM zones;` et lance avec le bouton ▶ ou F5 : 265.

@@ hints
- Le volume de la leçon 5 s'appelle `ny_taxi_postgres_data` : réutilise-le, avec les mêmes identifiants (`root`) que lorsque la base a été créée.
- Les deux `docker run` ont besoin de `--network=dez-net` et d'un `--name`.
- Dans pgAdmin : clic droit sur Servers, Register, Server. Onglet Connection, Host = le nom du conteneur Postgres.

@@ solution
~~~bash
# Le réseau qui relie les deux conteneurs par leur nom
docker network create dez-net

# Postgres, nommé db, sur le réseau, avec le volume (et les tables) de la leçon 5

docker run -d --name db --network=dez-net \
  -e POSTGRES_USER="root" -e POSTGRES_PASSWORD="root" -e POSTGRES_DB="ny_taxi" \
  -v ny_taxi_postgres_data:/var/lib/postgresql \
  -p 5432:5432 postgres:18

# pgAdmin sur le même réseau ; ses réglages dans le volume pgadmin_data
docker run -d --name pgadmin --network=dez-net \
  -e PGADMIN_DEFAULT_EMAIL="moi@exemple.com" -e PGADMIN_DEFAULT_PASSWORD="motdepasse" \
  -v pgadmin_data:/var/lib/pgadmin \
  -p 8085:80 dpage/pgadmin4
~~~
Dans pgAdmin : Host `db`, Port `5432`, Username `root`, Password `root`. Host vaut `db` parce que pgAdmin et Postgres sont deux conteneurs du même réseau : ils se trouvent par leur nom. `localhost` désignerait le conteneur pgAdmin lui-même.

@@ breakfix
Supprime le conteneur pgAdmin et relance-le **sans** `--network`. Essaie d'enregistrer le serveur avec Host `db` et lis l'erreur. Ensuite, **sans redémarrer pgAdmin**, connecte-le au réseau avec une commande Docker.

@@ breakfix-hints
- L'erreur dit que le nom `db` est inconnu : pgAdmin n'est pas sur le réseau où ce nom existe.
- La commande `docker network` a une sous-commande pour brancher un conteneur déjà lancé.
- `docker network inspect dez-net` liste les conteneurs branchés sur le réseau.

@@ breakfix-answer
Sans le réseau, le nom `db` ne veut rien dire pour pgAdmin : l'erreur parle d'un nom d'hôte qui ne se résout pas. `docker network connect dez-net pgadmin` branche le conteneur à chaud, et l'enregistrement marche. Docker Compose (leçon 9) fera tout ça pour toi.

@@ zoom
### Pourquoi `localhost` ne marche pas

Chaque conteneur a son propre réseau, avec son propre `localhost`. Quand pgAdmin cherche `localhost:5432`, il se cherche **lui-même**, et il n'y a pas de Postgres dans le conteneur pgAdmin. Le `-p 5432:5432` de la leçon 4 ne change rien : il ouvre une porte vers ton Codespace, pas vers les autres conteneurs.

### Un réseau, et des noms

`docker network create dez-net` crée un réseau. Les conteneurs lancés avec `--network=dez-net` s'y voient, et Docker y sert d'**annuaire** : le nom donné par `--name db` devient une adresse. Dans pgAdmin, l'hôte de la base est donc `db`. Le port est celui **du conteneur** (5432), pas celui publié avec `-p`.

| Qui parle | À qui | Adresse à utiliser |
| --- | --- | --- |
| Ton Codespace (pgcli) | Postgres | `localhost` et le port publié par `-p` |
| pgAdmin, dans un conteneur | Postgres, sur le même réseau | `db`, le nom du conteneur, et le port 5432 |
| Ton navigateur | pgAdmin | le port publié, ici 8085 |

Cette règle revient partout dans le cours : à la leçon 8 avec `--pg-host`, avec Docker Compose à la leçon 9, puis dans Airflow et Kafka.

>>> --name pgdatabase
**Ce que « Stop both containers » veut dire, étape par étape :**

1. **Arrête l'ancien Postgres :** va dans le premier terminal (celui des logs de Postgres) et fais Ctrl + C. Comme il avait `--rm`, il est supprimé. Vérifie avec `docker ps` : aucune ligne `postgres`.
2. **Premier terminal :** colle **seulement la première commande** du bloc (de `docker run` jusqu'à `postgres:18`). Les lignes `#` sont des commentaires. Attends `database system is ready to accept connections`.
3. **Deuxième terminal** (bouton **+**) : c'est le sens de « In another terminal ». Colle la deuxième commande (de `docker run` jusqu'à `dpage/pgadmin4`). Le premier démarrage prend une bonne minute ; attends une ligne avec `Listening at: http://[::]:80`.
4. **Vérifie** dans un troisième terminal : `docker ps` montre deux lignes, `pgdatabase` et `pgadmin`.

Tes données sont toujours là : c'est le même volume `ny_taxi_postgres_data` qu'à la leçon 4, donc la table `yellow_taxi_trips` de la leçon 6 existe encore.

**Les erreurs fréquentes :**

- `The container name "/pgdatabase" is already in use` : un ancien conteneur porte ce nom. Ces commandes n'ont **pas** `--rm`, donc un conteneur arrêté reste. Supprime-le avec `docker rm pgdatabase` (ou `docker rm pgadmin`), puis relance.
- `port is already allocated` : un autre conteneur utilise déjà le port. `docker ps` pour le trouver, `docker stop <son nom>` pour l'arrêter.

>>> # Connect pgAdmin to PostgreSQL
**Dans un Codespace, `http://localhost:8085` ne marche pas dans ton navigateur** : localhost, c'est ton PC, pas le Codespace. Fais plutôt :

1. En bas, à côté de **Terminal**, ouvre l'onglet **Ports**.
2. Sur la ligne **8085**, survole l'adresse et clique sur l'icône du **globe** (Open in Browser). Un nouvel onglet s'ouvre, avec une adresse du type `https://<nom>-8085.app.github.dev`.
3. Tu dois voir la page de connexion de pgAdmin. Si la page reste blanche ou affiche une erreur, attends une minute : pgAdmin n'a pas fini de démarrer.

Ensuite, suis la liste du texte. Dans les versions récentes, tu peux aussi cliquer sur **Add New Server** sur la page d'accueil de pgAdmin, au lieu du clic droit sur **Servers**. Dans l'onglet **Connection**, coche **Save password** pour ne pas le retaper.

**Ce que tu dois voir après Save :** à gauche, **Servers**, **Local Docker**, **Databases**, **ny_taxi**, **Schemas**, **public**, **Tables** : tes tables `test`, `yellow_taxi_data` et `yellow_taxi_trips`.

**Vérifie avec une requête :** clic droit sur **ny_taxi**, **Query Tool**. Écris `SELECT COUNT(1) FROM yellow_taxi_trips;` puis appuie sur **F5** (ou le bouton ▶). Le résultat `1369765` s'affiche en bas, dans **Data Output**.

**Pourquoi `pgdatabase` et pas `localhost` :** pgAdmin tourne dans **son** conteneur. Pour lui, `localhost` c'est lui-même. Sur le réseau `pg-network`, il trouve Postgres par son nom de conteneur, `pgdatabase`.
