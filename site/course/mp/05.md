@@ brief
- Le tableau de bord doit avoir **au moins deux graphiques** (*tiles*) pour les 4 points : la grille suggère une **répartition par catégorie** et une **évolution dans le temps**.
- **Looker Studio** (gratuit, branché sur BigQuery en quelques clics) ou **Streamlit** (une appli Python) : les deux sont cités par le cours. Looker Studio est le plus rapide ; Streamlit se met dans le dépôt et se relit comme du code.
- Chaque graphique a un **titre** qui dit ce qu'il montre, des axes nommés, et une phrase qui dit quoi regarder.
- Tes relecteurs doivent pouvoir **l'ouvrir** : un lien public en lecture, ou une capture d'écran dans le README si le lien risque d'expirer.

@@ codespaces
- Looker Studio se fait dans ton navigateur, sur ton compte Google : rien à installer.
- Streamlit tourne dans ton Codespace (`uv add streamlit`, puis `uv run streamlit run app.py`), et s'ouvre par l'onglet **Ports**.

@@ verified
- Rien de ce jalon n'est testé ici : c'est ton tableau de bord.

@@ predict
Ton graphique dans le temps lit la table brute de 40 millions de lignes, et Looker Studio le recalcule à chaque ouverture. Qui paie, et combien de fois ? Comment l'éviter ?

@@ predict-answer
**Toi**, à chaque ouverture, à chaque filtre changé, pour chaque relecteur : Looker Studio envoie une requête BigQuery, qui lit la table entière si elle n'est pas filtrée sur sa partition. Le graphique doit lire ton **mart** du jalon 4, déjà agrégé (quelques centaines de lignes) : la requête coûte presque rien, et l'affichage est instantané.

@@ practice
Construis ton tableau de bord à deux graphiques sur tes marts, et rends-le accessible à tes relecteurs.

@@ constraints
- Un graphique de répartition par catégorie, et un graphique dans le temps
- Chaque graphique lit un mart du jalon 4, pas la table brute
- Chaque graphique a un titre, des axes ou une légende lisibles, et une phrase d'explication
- Un lien public en lecture, ou l'appli Streamlit avec ses instructions, est dans le README
- Une capture d'écran du tableau de bord est dans le dépôt et dans le README

@@ guide
### 1. Choisir l'outil

Looker Studio si tu veux finir vite ; Streamlit si tu veux que le tableau de bord soit du code relu dans tes pull requests.

### 2. Les deux graphiques

Pour chaque graphique, écris d'abord la question à laquelle il répond, puis choisis le type : des barres pour comparer des catégories, une ligne pour le temps.

### 3. Le partage

Dans Looker Studio : **Partager > Gérer l'accès**, « Toute personne disposant du lien peut afficher ». Ouvre le lien dans une fenêtre de navigation privée pour vérifier.

@@ hints
- Trop de catégories rendent un graphique illisible : garde les 10 premières, et regroupe le reste en « Autres ».
- Une date en axe : choisis la bonne granularité (jour, semaine, mois) selon ta période.
- Dans Looker Studio, la source de données peut être une **requête personnalisée** : elle doit rester petite.
- Une capture d'écran survit à un compte Google fermé ou à un crédit gratuit épuisé.

@@ solution
Un exemple de section de README pour les vélos :

~~~markdown
## Le tableau de bord

[Ouvrir le tableau de bord](https://lookerstudio.google.com/...)

![Le tableau de bord](images/dashboard.png)

- **Les stations les plus déséquilibrées** (barres) : les 10 stations où partent le plus de vélos sans qu'il en revienne. Elles sont toutes près des gares : les vélos y manquent le matin.
- **Les trajets semaine après semaine** (ligne) : la courbe double entre février et juin, et chute les semaines de grève.
~~~

@@ selfcheck
- Mes deux graphiques répondent chacun à une question que je sais dire
- Un inconnu peut ouvrir mon tableau de bord, ou au moins le voir en capture
- Mes graphiques lisent des tables agrégées

@@ breakfix
Fais le test de l'inconnu : envoie le lien de ton tableau de bord à quelqu'un qui ne connaît pas ton projet, sans rien expliquer. Demande-lui ce qu'il comprend de chaque graphique en 10 secondes. Ce qu'il ne comprend pas est à corriger : titre, légende, ou choix du graphique.

@@ breakfix-hints
- Si on te demande « c'est quoi, cette couleur ? », il manque une légende.
- Si on te demande « c'est quand ? », il manque la période dans le titre.
- Si on ne voit pas où regarder, ajoute la phrase d'explication.

@@ breakfix-answer
Il n'y a pas de réponse unique : c'est un test d'utilisateur. Les défauts les plus courants dans les projets relus : un titre technique (`count_trips_by_station_id`) au lieu d'une question, un axe sans unité, trop de catégories, un graphique en camembert pour des valeurs proches. Les relecteurs de la cohorte notent le tableau de bord en le regardant quelques secondes : ce qu'un inconnu comprend en 10 secondes, ils le comprendront aussi.

@@ explain
Pourquoi le cours demande-t-il exactement ces deux types de graphiques, une catégorie et une évolution dans le temps ? Que montre chacun que l'autre ne montre pas ?
