@@ brief
- **dbt** (*data build tool*) transforme les données **déjà dans l'entrepôt**, avec des fichiers `.sql` qui contiennent chacun un simple `SELECT`. dbt crée la table ou la vue, dans le bon ordre.
- **dbt Core** est gratuit et se lance en ligne de commande. **dbt Cloud** est la version hébergée, avec un éditeur web. Ici : dbt Core, avec l'adaptateur **dbt-duckdb**.
- Un **projet** dbt est un dossier avec un `dbt_project.yml`. Le **profil**, dans `~/.dbt/profiles.yml`, dit à quelle base se connecter. Il reste **hors** du dépôt Git.
- Un profil a plusieurs **targets** (cibles) : `dev` pour travailler sur un échantillon, `prod` pour tout construire.

@@ guide
### 1. Le projet Python

~~~bash
mkdir -p /workspaces/data-engineering-zoomcamp/mon-travail/module-04
cd /workspaces/data-engineering-zoomcamp/mon-travail/module-04
uv init --bare --python=3.13
uv add "dbt-duckdb==1.11.1" requests
printf '*.duckdb\n*.duckdb.wal\ndata/\n' > .gitignore
~~~

`dbt-duckdb` installe aussi `dbt-core` et DuckDB. `requests` sert au script de chargement.

### 2. Les données

Ouvre le [guide d'installation officiel](https://github.com/DataTalksClub/data-engineering-zoomcamp/blob/main/04-analytics-engineering/setup/local_setup.md), étape 4 : le script télécharge les CSV, les convertit en Parquet, et crée `prod.green_tripdata` et `prod.yellow_tripdata`. C'est de la préparation, pas l'exercice : copie-le dans `charger.py`. Lis-le d'abord, et repère les trois étapes, puis :

~~~bash
uv run python charger.py
~~~

Une fois fini, les fichiers de `data/` ne servent plus : les tables DuckDB contiennent une copie des données. Pour récupérer 2 Go, `rm -rf data/`.

### 3. Le projet dbt

~~~bash
uv run dbt init mon_taxi --skip-profile-setup
rm -rf mon_taxi/models/example
~~~

`--skip-profile-setup` évite les questions interactives : tu écris le profil toi-même, juste après. Ouvre `mon_taxi/dbt_project.yml` : à la fin, supprime le bloc `example:` des `models:`, il désigne le dossier que tu viens d'effacer.

### 4. Le profil

`mkdir -p ~/.dbt && code ~/.dbt/profiles.yml`. Un profil a cette forme, ici pour un autre projet :

~~~yaml
ma_boutique:
  target: dev
  outputs:
    dev:
      type: duckdb
      path: /workspaces/data-engineering-zoomcamp/mon-travail/boutique/boutique.duckdb
      schema: boutique_dev
      threads: 1
      settings:
        memory_limit: '2GB'
~~~

Écris le tien : le nom du profil est celui de `dbt_project.yml`, deux outputs `dev` et `prod`, le **chemin complet** de ton fichier DuckDB (un chemin relatif dépend du dossier d'où tu lances dbt).

### 5. Vérifie

~~~bash
cd mon_taxi
uv run dbt debug
~~~

`uv run` trouve le `pyproject.toml` du dossier parent : pas besoin de remonter. Puis `git status` depuis la racine du fork.

@@ hints
- `dbt init` crée son propre `.gitignore` dans `mon_taxi/` : il ignore déjà `target/`, `dbt_packages/` et `logs/`.
- Si `dbt debug` dit `Could not find profile named ...`, compare lettre par lettre la ligne `profile:` de `dbt_project.yml` et la première ligne de `profiles.yml`.
- Si `dbt debug` ne trouve pas `dbt_project.yml`, tu n'es pas dans le dossier `mon_taxi`.
- La première ligne d'un output, `type: duckdb`, dit quel adaptateur utiliser. Les espaces au début des lignes comptent en YAML : deux par niveau.

@@ solution
`~/.dbt/profiles.yml` :

~~~yaml
mon_taxi:                      # le nom écrit dans dbt_project.yml (profile: 'mon_taxi')
  target: dev                  # la target utilisée quand tu ne précises rien
  outputs:
    dev:
      type: duckdb
      path: /workspaces/data-engineering-zoomcamp/mon-travail/module-04/taxi_rides_ny.duckdb
      schema: mon_dev          # tes modèles de travail vont dans ce schéma
      threads: 1
      settings:
        memory_limit: '2GB'
        preserve_insertion_order: false
    prod:
      type: duckdb
      path: /workspaces/data-engineering-zoomcamp/mon-travail/module-04/taxi_rides_ny.duckdb
      schema: mon_prod
      threads: 1
      settings:
        memory_limit: '2GB'
        preserve_insertion_order: false
~~~

La fin de `uv run dbt debug` :

~~~text
  profiles.yml file [OK found and valid]
  dbt_project.yml file [OK found and valid]
Connection:
  ...
  Connection test: [OK connection ok]

All checks passed!
~~~

@@ breakfix-hints
- Le premier message dit qu'un **profil** est introuvable. Lequel ? Cherche-le dans `~/.dbt/profiles.yml`.

@@ breakfix-answer
Avec le mauvais nom :

~~~text
Profile loading failed for the following reason:
Runtime Error
  Could not find profile named 'mon-taxi'
~~~

Depuis le dossier parent, dbt ne trouve pas de projet : `dbt_project.yml file [ERROR not found]`. dbt cherche toujours le projet dans le **dossier courant** (et le profil dans `~/.dbt/`). Chaque commande dbt se lance depuis `mon_taxi/`, ou avec `--project-dir mon_taxi`.
