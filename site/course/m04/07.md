@@ brief
- Un test dbt est une requête qui cherche les **lignes fautives**. Zéro ligne : le test passe. Une ou plusieurs : il échoue, et `dbt` se termine avec un code d'erreur.
- Les **tests génériques** se déclarent en YAML, sur une colonne : `unique`, `not_null`, `accepted_values`, `relationships` (chaque valeur existe dans une autre table). dbt_utils en ajoute d'autres, comme `unique_combination_of_columns`.
- Un **test singulier** est un fichier `.sql` dans `tests/`, qui renvoie les lignes fautives.
- `dbt test` lance les tests ; `dbt build` construit **et** teste chaque modèle dans l'ordre, et s'arrête avant les modèles qui dépendent d'un test raté.
- `severity: warn` transforme un échec en avertissement : pour un problème connu qu'on surveille sans bloquer.

@@ codespaces
- Les tests se déclarent dans des fichiers `.yml` à côté des modèles, par exemple `models/staging/schema.yml`. Le nom du fichier est libre, seul son contenu compte.
- `uv run dbt test --select stg_green_tripdata` lance seulement les tests d'un modèle.

@@ verified
- Testé avec dbt 1.12.6 en `dev` : les tests génériques du projet officiel passent tous. Le test singulier sur les montants négatifs trouve **2 561** trajets verts, et le test d'unicité sur `int_trips_unioned` trouve **197 523** combinaisons en double.
- Un test qui échoue fait sortir `dbt test` avec le code 1 (`echo $?` juste après) : c'est ce code que lit une CI.

@@ guide
### 1. Des tests génériques

Un fichier YAML décrit des modèles et leurs colonnes. Exemple :

~~~yaml
models:
  - name: dim_clients
    columns:
      - name: client_id
        data_tests:
          - unique
          - not_null
      - name: pays
        data_tests:
          - accepted_values:
              arguments:
                values: ['France', 'Maroc']
~~~

Écris `models/staging/schema.yml` et `models/marts/schema.yml`. Pour `relationships`, les arguments sont `to: ref('dim_zones')` et `field: location_id`.

### 2. Lance-les

~~~bash
uv run dbt test
~~~

Chaque test a un nom généré : `not_null_stg_green_tripdata_vendor_id`, par exemple.

### 3. Un test singulier

Un fichier `.sql` dans `tests/` : un `select` qui renvoie les lignes **fautives**. Exemple :

~~~sql
-- Un client ne peut pas être né dans le futur
select * from {{ ref('dim_clients') }} where date_naissance > current_date
~~~

Écris le tien sur `total_amount < 0`, en gardant `pickup_datetime`, `payment_type` et `total_amount`.

### 4. Regarde ce qu'il trouve

~~~bash
uv run dbt test --select assert_total_amount_non_negatif
~~~

La sortie donne le chemin du SQL compilé, dans `target/compiled/`. Lance-le avec `dbt show --inline`, en ajoutant un `group by payment_type`.

### 5. Décide

En première ligne du test : `{{ config(severity='warn') }}`, et un commentaire qui dit pourquoi. Puis `uv run dbt build`.

@@ hints
- Avec dbt 1.10 et plus, les arguments d'un test générique vont sous `arguments:`. L'ancienne écriture, sans `arguments:`, marche encore mais affiche un avertissement.
- Si `dbt test` ne trouve pas ton test singulier, vérifie qu'il est dans le dossier `tests/`, à la racine du projet, pas dans `models/`.
- La correspondance des codes de paiement est dans ton seed `payment_type_lookup` : 3 = *No charge*, 4 = *Dispute*.

@@ git
Un test passait hier et échoue aujourd'hui, et dix commits ont été faits entre les deux. Plutôt que de les relire un par un, Git peut trouver **le** commit fautif par dichotomie. Essaie-le : sur une branche d'essai, fais 6 petits commits sur un modèle, dont un, au milieu, qui casse un test (par exemple, retirer le `where vendorid is not null`). Puis retrouve-le avec `git bisect`.

@@ git-hints
- `git bisect start`, puis `git bisect bad` (le commit actuel est cassé), puis `git bisect good <hash>` (un commit où tout marchait).
- Git te place au milieu. Lance ton test, puis dis `git bisect good` ou `git bisect bad`. En 3 étapes, il trouve le coupable parmi 6.
- `git bisect run uv run dbt test --select stg_green_tripdata` le fait tout seul : le code de sortie de dbt dit bon ou mauvais. `git bisect reset` te ramène où tu étais.
