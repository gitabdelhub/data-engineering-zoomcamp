@@ brief
- Les **marts** sont la couche que lisent les analystes et les tableaux de bord : une table de faits, ses dimensions, et des tables de **reporting** déjà agrégées.
- `fct_trips` est la table de faits : un trajet par ligne, enrichi des noms de zones par deux jointures sur `dim_zones` (départ et arrivée).
- Une matérialisation **incrémentale** ne recalcule pas tout à chaque `dbt run` : elle ajoute seulement les nouvelles lignes. `is_incremental()` est vrai quand la table existe déjà ; `{{ this }}` désigne la table elle-même.
- `fct_monthly_zone_revenue` agrège par zone, mois et type de taxi : c'est la table qu'interroge le homework.

@@ constraints
- `models/marts/fct_trips.sql` lit `int_trips` et joint **deux fois** `dim_zones` : une pour la zone de départ, une pour l'arrivée, avec leur arrondissement (`borough`) et leur nom

@@ guide
### 1. La configuration incrémentale

En haut d'un modèle, un bloc `config` remplace ce que dit `dbt_project.yml`. Exemple :

~~~sql
{{
  config(
    materialized='incremental',
    unique_key='ticket_id',
    incremental_strategy='merge'
  )
}}
~~~

`unique_key` et `merge` : si une ligne arrive avec un `trip_id` déjà présent, elle remplace l'ancienne au lieu de faire un doublon.

### 2. Les deux jointures sur la même dimension

Une table peut être jointe deux fois, avec deux alias :

~~~sql
from {{ ref('int_trips') }} as trips
left join {{ ref('dim_zones') }} as pz on trips.pickup_location_id = pz.location_id
left join {{ ref('dim_zones') }} as dz on trips.dropoff_location_id = dz.location_id
~~~

`pz.zone as pickup_zone`, `dz.zone as dropoff_zone`. `left join` : un trajet vers une zone inconnue reste dans les faits.

### 3. Le filtre incrémental

À la fin du modèle :

~~~sql
{% if is_incremental() %}
  where trips.pickup_datetime > (select max(pickup_datetime) from {{ this }})
{% endif %}
~~~

Au tout premier lancement, la table n'existe pas : `is_incremental()` est faux, tout est chargé.

### 4. La table de reporting

Un `group by` sur trois dimensions : la zone (`coalesce(pickup_zone, 'Unknown Zone')`), le mois et le type de taxi. Le mois en DuckDB : `date_trunc('month', pickup_datetime)`. Puis une somme par montant (`fare_amount`, `extra`, `mta_tax`, `tip_amount`, `tolls_amount`, `ehail_fee`, `improvement_surcharge`, `total_amount`), un `count(trip_id)` et deux `avg`. Nomme-les comme le projet officiel (`revenue_monthly_fare`, `total_monthly_trips`…) : tu pourras comparer.

### 5. Construis, puis relance

~~~bash
uv run dbt run --select +fct_monthly_zone_revenue
uv run dbt run --select fct_trips
~~~

Compare les durées des deux `fct_trips` dans la sortie.

@@ hints
- La macro s'appelle avec les noms complets des colonnes : `{{ get_trip_duration_minutes('trips.pickup_datetime', 'trips.dropoff_datetime') }} as trip_duration_minutes`.
- Dans le filtre incrémental, `{{ this }}` est la table `fct_trips` déjà construite. Ne mets pas `ref('fct_trips')` : un modèle ne peut pas dépendre de lui-même.
- `group by` avec les alias (`group by pickup_zone, revenue_month, service_type`) marche en DuckDB. `group by all` aussi.
- Si `fct_monthly_zone_revenue` dit `Table with name fct_trips does not exist`, tu l'as construite seule, avant `fct_trips` : lance-la avec le `+` devant.

@@ solution
Les deux fichiers du projet officiel sont la référence : `04-analytics-engineering/taxi_rides_ny/models/marts/fct_trips.sql` et `models/marts/reporting/fct_monthly_zone_revenue.sql`, dans ton fork. Voici `fct_trips.sql`, raccourci et commenté :

~~~sql
{{
  config(
    materialized='incremental',     -- les lancements suivants ajoutent seulement les nouveautés
    unique_key='trip_id',           -- un trajet déjà présent est remplacé, pas doublé
    incremental_strategy='merge',
    on_schema_change='append_new_columns'
  )
}}

select
    trips.trip_id, trips.vendor_id, trips.service_type, trips.rate_code_id,
    -- la même dimension, jointe deux fois
    trips.pickup_location_id, pz.borough as pickup_borough, pz.zone as pickup_zone,
    trips.dropoff_location_id, dz.borough as dropoff_borough, dz.zone as dropoff_zone,
    trips.pickup_datetime, trips.dropoff_datetime, trips.store_and_fwd_flag,
    trips.passenger_count, trips.trip_distance, trips.trip_type,
    {{ get_trip_duration_minutes('trips.pickup_datetime', 'trips.dropoff_datetime') }} as trip_duration_minutes,
    trips.fare_amount, trips.extra, trips.mta_tax, trips.tip_amount, trips.tolls_amount,
    trips.ehail_fee, trips.improvement_surcharge, trips.total_amount,
    trips.payment_type, trips.payment_type_description
from {{ ref('int_trips') }} as trips
left join {{ ref('dim_zones') }} as pz on trips.pickup_location_id = pz.location_id
left join {{ ref('dim_zones') }} as dz on trips.dropoff_location_id = dz.location_id

{% if is_incremental() %}
  -- seulement les trajets plus récents que le plus récent déjà chargé
  where trips.pickup_datetime > (select max(pickup_datetime) from {{ this }})
{% endif %}
~~~
