@@ brief
- **MCP** (*Model Context Protocol*) est un protocole qui permet à un agent IA d'utiliser des outils. `bruin mcp` démarre un serveur MCP : l'agent peut alors lire la documentation de Bruin, ton pipeline, et lancer des commandes comme `bruin query`.
- Dans VS Code, avec GitHub Copilot en mode agent, le serveur se déclare dans `.vscode/mcp.json`. D'autres agents (Cursor, Claude Code) ont leur propre réglage.
- L'agent peut écrire des assets, expliquer un pipeline, ou répondre à une question sur les données en écrivant le SQL à ta place. Il peut aussi **se tromper** : chaque réponse se vérifie.
- **Bruin Cloud** fait tourner les mêmes pipelines sur des serveurs gérés : il lit ton dépôt GitHub, stocke les connexions à la place de `.bruin.yml`, et lance chaque pipeline selon son `schedule`.

@@ codespaces
- Copilot a une offre gratuite, limitée en nombre de requêtes par mois : assez pour cette leçon. Si tu n'as pas Copilot, fais la leçon en lisant, et réponds aux questions toi-même avec `bruin query`.
- Bruin Cloud demande un compte et l'accès à ton dépôt. Cette partie est **facultative** : regarde la vidéo, sans rien déployer.

@@ predict
Tu demandes à l'agent : « Quel jour de janvier 2019 a eu le plus de trajets verts ? ». Il répond avec un jour et un nombre. Comment sais-tu s'il a raison, sans lui faire confiance ?

@@ predict-answer
Tu lui demandes **la requête** qu'il a lancée, tu la lis, puis tu la relances toi-même avec `bruin query`. Une réponse juste a une requête juste : la bonne table (`reports.trips_report` ou `staging.trips`), le bon filtre (janvier, les verts), la bonne agrégation (une **somme** de `trip_count` par jour dans le rapport, pas un `count(*)` de ses lignes). Si l'agent lit le rapport et compte ses lignes, il trouve le nombre de combinaisons jour, taxi et paiement, pas le nombre de trajets.

@@ practice
Branche Bruin MCP à Copilot, pose-lui trois questions sur ton pipeline et tes données, et vérifie chaque réponse toi-même.

@@ constraints
- `.vscode/mcp.json`, à la racine de ton fork, déclare le serveur `bruin` avec la commande `bruin mcp`
- `mon-travail/module-05/agent.md` : trois questions posées à l'agent, ses réponses, et pour chacune ta vérification (la requête que tu as lancée, ou le fichier que tu as lu)
- Au moins une question sur les **données** (un nombre) et une sur le **pipeline** (quel asset fait quoi)
- Une phrase par réponse : juste, fausse, ou à moitié, et pourquoi
- L'agent n'écrit aucun fichier de ton pipeline : il lit et il interroge

@@ guide
### 1. Le serveur MCP

`.vscode/mcp.json` :

~~~json
{
  "servers": {
    "bruin": {
      "type": "stdio",
      "command": "bruin",
      "args": ["mcp"]
    }
  }
}
~~~

Ouvre le fichier dans VS Code : un bouton **Start** apparaît au-dessus du serveur. Puis ouvre la vue Copilot, passe en mode **Agent**, et vérifie dans la liste des outils que ceux de Bruin sont là.

### 2. Trois questions

Des idées :

- « Dans mon-travail/module-05/mon-pipeline, quel asset dédoublonne les trajets, et sur quelles colonnes ? »
- « Combien de trajets verts y a-t-il dans staging.trips pour février 2019 ? »
- « Quel type de paiement a le prix moyen le plus élevé dans le rapport ? »

Demande toujours : « Montre-moi la requête que tu as lancée. »

### 3. Vérifie

Relance chaque requête avec `bruin query --connection duckdb-default --query "..."`, ou ouvre le fichier cité. Note ce que tu trouves.

@@ hints
- Si l'agent ne voit pas les outils de Bruin, vérifie que `bruin` est dans le `PATH` du terminal de VS Code : `which bruin`.
- Si l'agent veut modifier un fichier, refuse : cette leçon porte sur la lecture et la vérification.
- Une moyenne sur le rapport n'est pas la moyenne des trajets : `avg(avg_fare)` donne le même poids à un jour de 10 trajets et à un jour de 10 000. Vérifie sur `staging.trips`.

@@ solution
Un exemple de `agent.md`, à comparer avec le tien :

~~~markdown
## 1. Quel asset dédoublonne les trajets ?
Agent : staging.trips, avec QUALIFY ROW_NUMBER() sur les dates, les zones, le prix et le type de taxi.
Vérification : j'ai ouvert mon-pipeline/pipeline/assets/staging/trips.sql. Juste.

## 2. Combien de trajets verts en février 2019 dans le staging ?
Agent : 575 646, avec un count(*) filtré sur pickup_datetime en février et taxi_type = 'green'.
Vérification : même requête avec bruin query, même nombre. Juste.

## 3. Quel paiement a le prix moyen le plus élevé ?
Agent : il a pris avg(avg_fare) sur le rapport.
Vérification : avg(fare_amount) par paiement, sur staging.trips. À moitié : la méthode est fausse,
la moyenne des moyennes donne le même poids à chaque jour, même s'il n'a que 3 trajets.
~~~

Le nombre de février vient de mon test ; ton agent doit trouver le nombre de **ton** staging. Ce qui compte : chaque réponse a sa vérification, et tu sais dire pourquoi une réponse est fausse.

@@ breakfix
Dans `.vscode/mcp.json`, remplace `"bruin"` par `"bruinn"` dans `command`, et redémarre le serveur. Que dit VS Code ? Que répond l'agent si tu lui poses une question sur tes données ? Répare.

@@ breakfix-hints
- La vue **Output** de VS Code a un canal par serveur MCP : choisis celui de `bruin`.
- Un serveur qui ne démarre pas ne fournit aucun outil : l'agent n'a plus que ce qu'il sait déjà.
- Écoute bien la réponse de l'agent : dit-il qu'il n'a pas accès aux données, ou invente-t-il un nombre ?

@@ breakfix-answer
Le serveur ne démarre pas : le canal **Output** du serveur `bruin` signale une commande introuvable, et ses outils disparaissent de la liste. Un bon agent te dit alors qu'il ne peut pas interroger ta base. Un agent moins prudent répond quand même, avec un nombre plausible qu'il n'a lu nulle part. C'est la vraie leçon : une réponse sans requête vérifiable ne vaut rien. Remets `"bruin"` et redémarre le serveur.
