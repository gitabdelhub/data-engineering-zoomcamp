@@ brief
- Un **producteur** envoie des messages à un topic avec `KafkaProducer(bootstrap_servers=[...], value_serializer=...)`, puis `producer.send(topic, value=...)`.
- Kafka ne transporte que des **octets**. Le **sérialiseur** transforme ton objet Python en octets : ici, une `dataclass` `Ride` → un dictionnaire → du JSON → `encode("utf-8")`.
- `send` est **asynchrone** : il met le message dans un tampon et rend la main. `producer.flush()` attend que tout soit vraiment parti. Sans lui, un script qui se termine peut perdre ses derniers messages.
- Les dates voyagent en **millisecondes depuis 1970** (*epoch*) : un entier, sans ambiguïté de format, que Flink sait lire.

@@ predict
Ton producteur envoie 1 000 messages avec `send`, puis le script se termine, **sans** `flush()`. Combien de messages arrivent dans le topic : 1 000, aucun, ou ça dépend ?

@@ predict-answer
**Ça dépend.** `send` ne fait que remplir un tampon ; un fil d'exécution en arrière-plan envoie les lots. Si le script se termine avant, les derniers messages sont perdus. `kafka-python` essaie de vider le tampon à la fermeture, mais tu n'as aucune garantie, et aucune erreur. `flush()` à la fin, c'est la ceinture de sécurité : il bloque jusqu'à ce que le broker ait tout reçu.

### 2. Le modèle

Un exemple sur des commandes, à adapter :

~~~python
from dataclasses import dataclass

@dataclass
class Order:
    shop_id: int
    amount: float
    ordered_at: int  # millisecondes depuis 1970

def order_from_row(row):
    return Order(
        shop_id=int(row["shop_id"]),
        amount=float(row["amount"]),
        ordered_at=int(row["ordered_at"].timestamp() * 1000),
    )
~~~

### 3. Le producteur

~~~python
import dataclasses, json
from kafka import KafkaProducer

def serializer(obj):
    return json.dumps(dataclasses.asdict(obj)).encode("utf-8")

producer = KafkaProducer(bootstrap_servers=["localhost:9092"], value_serializer=serializer)
producer.send("orders", value=order)
producer.flush()
~~~

L'adresse des données et la liste des colonnes sont dans le texte de la leçon officielle, plus bas.

@@ breakfix-hints

- Le nom de l'erreur ne dit rien : lis la ligne de code que montre la trace.
- Une `str` Python n'est pas des `bytes`.

@@ breakfix-answer
Dans les deux cas, l'erreur arrive au `send`, avant tout envoi réseau : le producteur exige des `bytes` (ou `None`), et reçoit d'abord un `Ride`, puis une `str`. Et le message est presque vide : un simple `AssertionError`, sans explication, qui pointe une ligne `assert type(value_bytes) in (bytes, bytearray, memoryview, type(None))` au fond de la bibliothèque. Lire la ligne de la trace, pas seulement le nom de l'erreur, donne la réponse. Kafka ne connaît que des octets : c'est le producteur qui décide du format (JSON ici, souvent Avro ou Protobuf en entreprise), et le consommateur doit faire l'inverse exact. Si les deux ne sont pas d'accord, rien n'est vérifié par le broker.
